# v0.7.0 — 设备自动更新

正在运行的 `wanctl agent` 会自己保持最新：启动 60 秒后检查一次签名发布清单，之后每 6 小时再查一次，发现新版本就按 `wanctl update` 同样的验签与原子替换流程装上，然后重启进新版本。此前每个修复都要有人登录到每台设备上手动执行更新，而最需要修复的恰恰是没人登录的那些设备。

- 自动更新默认开启。关闭用 `wanctl config set auto_update=off`，也可以用环境变量 `WANCTL_AUTO_UPDATE`；设置在每次检查时重新读取，改完不必重启 agent。`wanctl status` 会显示当前是开启还是关闭。
- 有 shell 会话、后台任务或控制台会话正在进行时不更新，5 分钟后重试，不会打断正在做的事。
- macOS 与 Linux 上就地重启，进程号不变，systemd、launchd、pid 文件以及 `wanctl status` 和 `wanctl stop` 都照常可用；Windows 上由计划任务或原进程拉起继任进程。
- 取不到 GitHub 发布页时，自动更新和手动 `wanctl update` 都改从中继的 `/dl` 镜像下载，网络屏蔽 GitHub 的设备同样能更新。
- 开发版本、Android App 内的副本，以及装在不可写目录里的二进制不会被自动替换，只在日志里提示一次，不会以管理员身份重试。
- 本次不涉及 Android App、中继和门户，三者仍按各自的方式升级。

**桌面与服务器设备手动升级到本版之后即可自动更新，此后不需要再逐台执行 `wanctl update`。**
