# v0.2.3

**清账开源前的历史遗留：文案、文档、下载页，把「长在公司内网里」的痕迹全部清掉。**

## 使用文档回来了，而且改成管理员专属编辑

- 「使用文档」六篇全部按开源后的真实流程重写：公开发布的二进制没有内置地址，每篇都从 `export WANCTL_RELAY / WANCTL_PORTAL` 讲起；新增一篇「邀请、好友与共享」。文档的真源在仓库 `docs/portal/`，同步脚本推送时会把占位符换成你实例的域名。
- 文档站是所有人共用的一个面，从这版起**只有管理员能编辑**（网页和 CLI 两条路都收紧了）；其他人只读。

## 下载安装页修了两处

- 下载链接和一行安装命令此前用门户到 relay 的**内部地址**拼出来——compose 部署里那是容器网络名，浏览器根本打不开。现在用公网 relay 地址。
- 一行安装命令带上了 `WANCTL_RELAY=…` 前缀：开源发布的安装脚本没有内置 relay 地址，裸跑会报错。

## 其他

- 门户、relay 发的 AI skill、各处提示语里残留的「GitLab」「飞书」措辞改为与部署无关的说法；「重要机器从独立发布页装」现在指向 GitHub Releases。
- 没配飞书凭证的部署（GitHub OAuth 自部署实例都是），设备页不再显示那张永远发不出卡片的「飞书审批」卡。
- 已知缺口立案：`wanctl service install` 生成的开机自启单元不带 relay 地址，Linux/macOS 上需要手工补环境变量（[issue #2](https://github.com/Daily-AC/wanctl/issues/2)，文档里写了补法）。
