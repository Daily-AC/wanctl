# v0.3.3

**安全更新：把 2026-08-28 全面审查确认的高危边界一次收紧，并修复 Android 首次登录。**

建议所有 relay / portal 部署和设备端尽快升级。桌面与服务器运行 `wanctl update`；Android 在 App 内点「检查更新」。

## 设备端

- 文件传输永远不能再读写 agent 自己的身份、凭证、信任和策略目录，也不能覆盖正在运行的 wanctl 二进制。此前全局写规则或 bypass 模式会让文件通道碰到 `portal_admins.json` / `key.pem`，能把普通写权限升级成控制台管理员或窃取设备身份。
- Windows PowerShell 的命令前缀规则现在识别 PowerShell 自己的子表达式、scriptblock、反引号和语句分隔符，`ping @(恶意代码)` 这类写法不再绕过 `ping *`。
- 自动信任与门户配对会写入 `trust` 活动事件；`wanctl logs --type trust` 能回答何时接纳了哪个控制端。

## relay 与 portal

- HTTP 设备注册表按空间限额并清扫离线项；废弃 session 自动回收，且 up/down/close 只能由会话双方访问。一个 token 不能再靠伪造海量设备名把共享 relay 撑到 OOM。
- 所有 JSON / MCP 请求体都有按路由设置的硬上限；未认证的 enrollment 请求不能再用超大 JSON 吃光内存。
- 修复门户存储型 XSS、docs 路径穿越代理、OAuth 开放重定向，以及访问 enrollment 页面就遗留永久 token 的问题。
- 共享设备的控制台、活动日志、审批事件、信任指纹和通知邮箱恢复为 owner-only，不再借门户的特权连接越过 ACL。
- Android 登录只知道 portal 时，会从 `/api/instance` 自动发现并保存 relay；主屏也明确显示 portal / relay 或「未配置」。

## MCP 与发布链

- 共享 HTTP MCP 不再暴露宿主机文件路径或服务器日志；stdio 文件工具默认只能访问 MCP 启动目录，并始终排除 wanctl 凭证目录。
- 模型不能再自行接受 relay 刚刚给出的设备指纹。`wanctl_trust_server` 默认 fail-closed；stdio 模式由人在终端运行 `wanctl trust server`。旧行为只在管理员显式设置 `WANCTL_MCP_ALLOW_UNSAFE_TRUST_SERVER=1` 时恢复。
- 发布二进制、容器与 govulncheck 统一使用 Go 1.26.6。此前 v0.2.0-v0.3.2 的 release 二进制实际由 Go 1.25.5 编译，而扫描跑的是 1.26.6，造成绿色报告与出货 stdlib 不一致。
- GitHub Actions 全部固定到完整 commit SHA；签名 secrets 只进入需要它们的步骤；安全扫描、完整文件清单、签名与四个 Android APK 都是发布硬门禁。
- Windows 安装器强制 HTTPS、TLS 1.2+ 并拒绝重定向降级；Android keystore 不再出现在进程参数，失败退出也会清理落盘副本。

## 部署兼容提醒

- `WANCTL_ADMIN_SECRET` 设置时至少 32 字节。
- relay 的 `/skills` 必须配置 `WANCTL_PUBLIC_ORIGIN`；官方 Compose 已包含该变量，缺失时返回 503，不再信任请求 Host。
- `/admin/acl` 创建授权时必须显式给出 `perms`，不再把空值扩成 `exec,read,write`。

完整审查、仍开放的中低危项和架构取舍见 `docs/security-audit-2026-08-28.md`。
