# v0.23.1 — Windows 上敲中文不再乱码，设备传大文件时不再拖垮别的会话，shell 提示符上色

- **发到 Windows 设备的命令里的中文原样到达。** 以前 `echo 中文` 在 Windows 上会变成 `Σ╕¡µûç`：PowerShell 会话按系统的 OEM 代码页（437 或 936）去读收到的命令，而这个读法在会话里改不掉。受影响的是普通 `wanctl exec`、`wanctl workspace` 里的命令和 `-script`，以及 `wanctl shell`；`--oneshot` 和普通 `-script` 本来就没问题。现在命令以纯 ASCII 的形式送进会话，再原样还原执行，`cd` 和变量照样跨命令保留，退出码不变。
- **Windows 会话里的命令整段执行，和 `--oneshot`、`.ps1` 一致。** 顺带修好一个老问题：跨行的代码块（`if {` 换行再 `}`）以前会让会话一直卡到超时，现在没写完的语句直接报错退出。两个看得见的变化：一条命令里有多条语句时，它们的输出合在一起排版；顶层 `Write-Error` 的报错开头显示的是包装后的那一行，而不是你写的原文。
- **设备往外传大文件时，连它的其他会话不再被拖慢。** 以前设备上传大块数据时，会和它的心跳、新会话的握手挤在同一条连接上。上行慢的时候，一次 `wanctl status` 要几十秒，心跳也被堵住，relay 误以为设备掉线，把这台设备上所有会话一起断开。现在大块传输只走另外几条连接，限速 400 KB/s 的测试里，拉 256 MB 期间 `status` 从 31–41 秒降到约 1.2 秒，推送不再被中途切断。大块传输的连接从 4 条变成 5 条，吞吐不变。推送刚开始时的第一块数据（最多 2 MiB）还走原来那条连接，只影响推送开头的几秒。
- **relay 判断设备掉线更宽松。** 设备心跳停止 40 秒才算掉线（以前 15 秒），盖住设备心跳在慢链路上最长可能的间隔，不再误杀活着的设备。代价是：设备进程被杀后，正在跑的命令约 45 秒结束（以前约 20 秒）；断网约 70 秒。设备重启、自动更新、正常退出不受影响，仍是几秒内结束。
- **agent 不会再因为一次网络中断就永久退出。** 以前设备轮询 relay 时出现网络错误（超时、连接被断），只要错误信息里碰巧带着 `401` 三个字符，agent 就会当成凭证被拒，打印 `relay rejected token` 后退出、不再重连。错误信息里带着设备 ID、指纹和进程编号，所以大约 1–2% 的 agent 会碰上，设备 ID 里含 `401` 的设备每次断网都会碰上。现在网络错误一律等两秒重试，只有 relay 真的回了 401 才退出。
- **`wanctl shell` 的提示符像 ssh 一样上色。** 设备名绿色、目录蓝色，和命令输出一眼就能分开；设了 `NO_COLOR` 或 `TERM=dumb` 时不上色。设备名和目录里的控制字符照旧会被过滤，设备没法借提示符往你的终端里写控制序列。
- **`wanctl shell` 进入更快。** 查设备模式和建立连接改成同时进行，实测进入时间中位数 5090 从 2.75 秒降到 1.51 秒、一台海外虚拟机从 5.30 秒降到 3.53 秒。进去之后每敲一行的耗时取决于你到 relay、relay 到设备的网络，这一版没有变化。

兼容性：中文、大文件和 agent 不再误退出这三条都要设备 agent 升级到 v0.23.1 才生效；掉线判定随 relay 生效；`wanctl shell` 的两条只需要升级控制端。新旧版本可以混用，协议没有变化。无数据库迁移，无新增环境变量。
