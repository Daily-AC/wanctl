# v0.23.1 — Windows 上敲中文不再乱码，设备传大文件时不再拖垮别的会话

- **发到 Windows 设备的命令里的中文原样到达。** 以前 `echo 中文` 在 Windows 上会变成 `Σ╕¡µûç`：PowerShell 会话按系统的 OEM 代码页（437 或 936）去读收到的命令，而这个读法在会话里改不掉。受影响的是普通 `wanctl exec`、`wanctl workspace` 里的命令和 `-script`，以及 `wanctl shell`；`--oneshot` 和普通 `-script` 本来就没问题。现在命令以纯 ASCII 的形式送进会话，再原样还原执行，`cd` 和变量照样跨命令保留，退出码不变。
- **Windows 会话里的命令整段执行，和 `--oneshot`、`.ps1` 一致。** 顺带修好一个老问题：跨行的代码块（`if {` 换行再 `}`）以前会让会话一直卡到超时，现在没写完的语句直接报错退出。两个看得见的变化：一条命令里有多条语句时，它们的输出合在一起排版；顶层 `Write-Error` 的报错开头显示的是包装后的那一行，而不是你写的原文。
- **设备往外传大文件时，连它的其他会话不再被拖慢。** 以前设备上传大块数据时，会和它的心跳、新会话的握手挤在同一条连接上。上行慢的时候，一次 `wanctl status` 要几十秒，心跳也被堵住，relay 误以为设备掉线，把这台设备上所有会话一起断开。现在大块传输只走另外几条连接，限速 400 KB/s 的测试里，拉 256 MB 期间 `status` 从 31–41 秒降到约 1.2 秒，推送不再被中途切断。大块传输的连接从 4 条变成 5 条，吞吐不变。
- **relay 判断设备掉线更宽松。** 设备心跳停止 40 秒才算掉线（以前 15 秒），盖住设备心跳在慢链路上最长可能的间隔，不再误杀活着的设备。代价是：设备进程被杀后，正在跑的命令约 45 秒结束（以前约 20 秒）；断网约 70 秒。设备重启、自动更新、正常退出不受影响，仍是几秒内结束。

兼容性：中文那一条和大文件那一条都要设备 agent 升级到 v0.23.1 才生效；掉线判定随 relay 生效。新旧版本可以混用，协议没有变化。无数据库迁移，无新增环境变量。
