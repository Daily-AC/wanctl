# v0.20.3 — 开了审批手机的设备和 Windows 设备，自动更新恢复正常

- **开了审批手机的设备能自动更新了。** 门户为了把审批推到手机，会和每台设备一直连着一条控制台连接，而 agent 以前只要有控制台连着就算「正忙」。所以从 v0.20.0 起，这些设备每 5 分钟推迟一次自动更新，一直升不上去。现在只有命令或后台任务在跑，或者有请求在等你审批、配对时才算忙；审批结束（批准、拒绝或过期）后，下一次检查就会接着更新。
- **用 `wanctl service install` 装的 Windows 设备，每次都能自动更新了。** 常驻的 supervisor 一直在运行上一次更新留下的 `wanctl.exe.old`，下一次更新要覆盖这个正在运行的文件，Windows 拒绝（Access is denied），于是从第二次起所有更新都失败，直到重启电脑。现在遇到这种情况，被替换的版本改存成带时间戳的 `wanctl.exe.old-<时间>`；agent 每次启动会顺手删掉不再运行的旧备份。
- **在管理员终端里跑 `wanctl update`，能重启以 SYSTEM 身份运行的 agent 了。** 以前新版本装好了，重启那一步却悄悄失败，旧版本继续服务，只能手动重启计划任务。原因是 wanctl 终止进程的方式会触发一次不认管理员调试特权的权限检查；现在直接以终止权限打开进程，并在需要时启用调试特权。`wanctl stop` 同样受益。
- **已经卡住的设备要手动升一次。** 上面两种设备停在 v0.20.2 或更早时，更新跑的还是旧代码，自己升不到 v0.20.3：开了审批手机的设备，在设备上运行一次 `wanctl update`；用 `wanctl service install` 装的 Windows 设备，先重启电脑（或注销再登录），再运行一次 `wanctl update`。升到 v0.20.3 之后，以后的版本都能自动更新。

兼容性：Windows 上替换二进制、终止 agent 的方式变了；「正忙」的判断对所有平台生效。无数据库迁移，无新增环境变量。
