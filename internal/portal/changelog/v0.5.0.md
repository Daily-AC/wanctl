# v0.5.0

**Ctrl-C 现在真的会停掉设备上的命令，第一次运行会问你连哪个 relay，内网快路径退场。**

relay / portal 部署升级后无需迁移数据库；桌面与服务器运行 `wanctl update`，Android 在 App 内点「检查更新」。**取消命令这一条要设备端也升级到本版才生效。**

## 控制端

- `wanctl exec --target <设备> -oneshot ...` 运行期间按 Ctrl-C，或控制端进程被杀、MCP 宿主放弃调用，设备上的命令会在一两秒内被终止：Unix 上杀整个进程组，Windows 上 `taskkill /T /F` 连同 shell、子进程和控制台宿主一起清掉。此前控制端退出后命令会在设备上跑到自然结束，没有人再读它的输出。

  控制端先在连接上发一帧取消，再关掉连接兜底。旧版本的设备收到取消帧不会出错，只是要等命令跑完才看得到，行为与升级前一样；要让取消生效，设备也得升到本版。控制端被取消时退出码为 130。

- 持久会话（不带 `-oneshot`）里的命令还不会随 Ctrl-C 终止：那个 shell 是长期共用的，杀掉前台子进程还是整个重开会话是一个产品决定，单独跟踪在 issue #46。需要中途放弃的命令请用 `-oneshot`。

- 刚装好的 `wanctl` 第一次运行需要 relay 的命令时，会在终端里问你：用项目的托管实例（仅限邀请，登录门户即可申请），还是你自己搭的 relay。答案通过 `wanctl config set` 同一条路径写入配置，只问一次。

  这一问只在人看得见的时候出现：已经配置过 relay（配置文件、`WANCTL_RELAY`、`--relay`、编译期默认值任一来源）、stdin 或 stdout 不是终端、或设了 `WANCTL_NO_PROMPT=1`，都不会问，而是直接给出两条 `wanctl config set` 命令让脚本和无人值守安装照旧失败得明白。Android 端保持原来的提示。

## 门户

- 设备页标题行的执行模式（逐条确认 / 全放行）从浏览器原生下拉框改成页面内的菜单。macOS 上 Chrome 把原生下拉框交给系统绘制，菜单按「当前项压住触发器」定位，会飘到药丸左上方盖住设备名，看起来像脱离了页面。现在菜单贴在药丸正下方左对齐，键盘可用（Enter/空格打开、方向键移动、Esc 关闭），切到「全放行」仍然先弹确认。

## 移除

- **内网快路径（LAN fast path）整体移除。** `wanctl net wan|lan|auto|status` 命令、agent 的 `--lan-relay`、`WANCTL_LAN_RELAY`、门户里的内网开关和设备状态里的 `lan` 字段都不存在了。没有任何部署启用过它，而它能给的东西一个 relay 地址就能给：想要内网延迟，在内网里跑一个 relay，`wanctl config set relay=...` 指过去即可（不带数据库的 relay 会向主 relay 校验令牌，见文档「Satellite relays」）。

  升级不需要你做任何清理：配置目录里残留的 `netmode`、`lan` 文件和还在导出的 `WANCTL_LAN_RELAY` 都会被忽略；旧版设备上报的 `lan` 字段门户照常解析。决定记录在 ADR 0005。

## 修复

- agent 现在拥有自己的全部 goroutine，`Close` 会等它们退出。此前测试偶尔在清理临时目录时撞上仍在写入的审计日志（CI 上的 flaky）。生产路径只多了一个有序退出。

## 自建部署提醒

- 没有新的数据库迁移，没有需要改动的配置。
- relay 与 portal 都要重建：取消帧走 relay 转发，门户界面内嵌在二进制里。
- 设备要升到本版取消才生效；升级前的设备与本版控制端搭配时行为与 v0.4.0 相同。
