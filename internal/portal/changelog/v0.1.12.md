# v0.1.12

**这一版全是"看起来正常、其实不对"的问题。** 起因是一个再普通不过的需求——查手机还剩多少电——结果发现根本查不了，顺藤摸出六个同类毛病：它们都不报错，只是安静地给你一个错的结果。

## 手机能查电量了

```
wanctl exec -target <手机> -- battery
```

返回电量百分比、充电状态、供电方式、温度、健康度。

之前这件事在 shell 里做不到，不是没人写，是安卓不让：agent 跑在应用沙箱最严的那一档权限里，`/sys/class/power_supply` 读不了（连列目录都不行），`dumpsys battery` 拿不到系统服务，没有 Termux 也没有 root。电量只存在于 Java 那一侧的系统接口后面，所以现在由 App 采集、命令行读取。

**数据太旧会直接说不知道**：文件缺失、损坏、或超过 10 分钟没更新，都会明确报"取不到"并说明原因，而不是给你一个看着新鲜的旧数字。

## `exec` 不再误读你的命令

**设备名可以直接写了。** `wanctl exec 手机 whoami` 现在就是你以为的意思。以前只认 `-target`，位置参数会被拼进命令——如果只有一台设备在线，`wanctl exec 手机 whoami` 会**把"手机 whoami"当成命令送过去执行**，你看到的报错像是设备坏了，其实是参数被吃了。

**引号丢了会警告。** 你写 `sh -c '一串脚本'`，本地 shell 早就把引号剥掉了，设备收到的是散开的词，通常**只执行第一个**。最坑的是它不报错：

- 写 `sh -c 'ls -d /某/路径; command -v pkg'`，实际只跑了 `ls`，打印出当前目录的内容，看着像"路径存在"
- 写 `for ... do ... done`，报一个莫名其妙的语法错
- 某个 `cat` 变成读标准输入，命令直接卡住

现在这些情况会提示你改用 `wanctl exec -script 脚本.sh`——文件走 base64 传输，不会被重新拆词。

## `status` 不再答非所问

`wanctl status -target 设备名` 现在查的是那台远端设备（在线状态、策略模式、agent 版本）。以前 `status` 会把你给的参数**全部忽略**，然后把**本机**的状态报给你，还不说明这是本机——很容易看着"运行中"就以为远端没问题。

## 服务端日志能直接拉了

```
wanctl logs --service portal|relay --since 30m --grep 关键词
```

以前排查服务端问题必须开浏览器、登平台控制台、用眼睛翻日志面板。现在命令行和 MCP 都能拉，输出会先脱敏再过滤。

## 飞书审批不再是黑盒

**开关旁边会显示上一次投递的结果**：什么时候、成功还是失败、失败的原因是什么、连续失败了多少次。以前发卡失败只写进服务端日志就没了，界面上开关照样显示"开"——"坏了"和"没开"长得一模一样。

设备的策略模式也显示出来了：**bypass 模式的设备不会产生任何审批请求**，所以那台设备的审批开关其实是摆设，现在界面上会告诉你这件事。

**一台掉线设备不会再刷爆日志。** 有台设备因为没在服务端注册，重试了 **17700 次**（每 5 分钟一条，持续了几个月），把其他所有日志都挤没了——真正出问题的时候反而查不到线索。现在这类永久性错误会让监听停下来并记下原因，设备重新注册或配置改动时自动恢复。

## 升级

协议和设备上的数据都没变，控制端和设备可以各升各的、不分先后。`battery` 需要手机装新版 App，其余改动装控制端或服务端就生效。
