# v0.14.0 — 大文件分摊到多条连接，Windows 后台任务不再弹窗

- **大文件推拉快了 2–3 倍。** 在丢包的跨境线路上，单条 TCP 连接就是速度上限。现在大传输会自动分摊到最多 4 条连接：上传按 1 MiB 一批分给各条连接，relay 按序号重排；下载时同时向 relay 要最多 4 个编了号的块，本地按顺序拼回。实测北京家宽经香港 relay 传 256 MB：push 从约 3.5 MB/s 提到 10.5 MB/s（已跑满家宽上行），pull 从 2.3–3.5 MB/s 提到 5–7 MB/s。传输途中断掉一条连接不会丢数据，会自动在其他连接上重发。
- **小命令不受影响。** 只有满 1 MiB 的上传批次和持续积压的下载才会开额外连接，exec 和小文件仍然只用一条连接，延迟与 v0.13.0 相同。
- **Windows 开机任务不再弹控制台窗口。** `wanctl service install` 注册的登录任务改成无窗口运行，修了三个会让 agent 掉线的问题：每次登录弹出一个控制台窗口、关掉它 agent 就下线；用电池时任务不启动、拔掉电源会被停止；运行 72 小时后被系统结束。agent 的输出改写到 agent.log，`wanctl service uninstall` 会把 agent 一起停掉。**已经装过服务的 Windows 设备，自动更新只换程序、不换任务，需要重新运行一次 `wanctl service install`。**

新旧版本可以混用：任何一端没升级，那一段就按原来的单连接工作，不会比 v0.13.0 慢。控制端、受控设备和 relay 都升级后才有完整提速。大传输在 relay 上每个方向最多暂存 16 MiB。无数据库迁移，无新增环境变量。
