# v0.23.0 — wanctl shell：像登录进设备一样直接敲命令

- **新命令 `wanctl shell 设备`。** 打开一个提示符，直接敲 `ls`、`cd`、`cat`，不用每条都写 `wanctl exec --target`。整个会话在设备上用同一个 shell，`cd` 和环境变量在行与行之间保留，从设备的家目录开始。提示符显示设备名和当前目录，上下键翻本次会话的历史，中文设备名和路径下光标位置正确。`exit` 或 Ctrl-D 退出并关掉设备上的这个 shell，直接关掉终端窗口也会关。
- **只能进 bypass 模式的设备。** normal 模式下规则没覆盖的命令要等设备主人审批，每敲一行等一次没法用。所以进入前先查设备模式，不是 bypass 就直接拒绝，并说明去门户的设备页切换，或者继续用 `wanctl exec`。
- **Ctrl-C 的行为和平常的 shell 一样。** 在提示符处只清空当前行；命令运行时按下会取消这条命令。取消会连带结束设备上的 shell，所以会在同一个目录开一个新的，之前设的环境变量会丢，界面会提示这一点。同一个 shell 跑满 128 条命令或输出接近设备给它的 8 MiB 上限时，也会这样换一个新的。
- **是行模式，不是终端。** 命令在设备上运行时没有终端，vim、top、less 这类全屏程序和要输密码的命令用不了。脚本和 AI 照旧用 `wanctl exec`。
- **工作区的命令结果带上当前目录。** `wanctl workspace` 和 MCP 的工作区结果多了 `cwd` 字段，是命令结束时 shell 所在的目录，`wanctl shell` 的提示符就靠它显示路径。
- **帮助首页的 `id` 挪到了 MORE 那一行**，给 `shell` 腾位置；`wanctl id` 本身不变。

兼容性：`wanctl shell` 只需要升级控制端。提示符里显示目录、以及 Ctrl-C 之后留在原目录，要设备 agent 也升级到 v0.23.0；对旧 agent，提示符只显示设备名，Ctrl-C 之后新 shell 从家目录开始。无数据库迁移，无新增环境变量。
