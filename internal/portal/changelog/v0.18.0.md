# v0.18.0 — 登录后先绑定邮箱

- **登录后需要绑定并确认一个邮箱。** 用 GitHub 登录以后，如果你还没有确认过的邮箱，会先到一张「绑定邮箱」页：填地址、点「发送确认信」，再到邮箱里点开链接、按「确认」就行。确认之前进不了门户，也提交不了访问申请。新申请人、老用户、管理员都一样。**为什么：** 以前申请人如果没留邮箱，申请通过了我们没法告诉他，只能等他哪天自己回来登录；以后账号相关的事（比如审批结果、安全提醒）也要靠邮件联系你。老用户第一次遇到这张页时，框里预填的是我们记录里的旧地址，确认一下即可。
- **确认链接的规矩。** 链接 24 小时内有效，只能用一次，只有最新发出的那一封有效。打开链接只会显示确认页，要按页面上的「确认」才生效，所以公司邮箱的安全扫描先点一遍链接不会替你确认。可以在手机上点：电脑上等着的那一页会自己往下走。为了防止被拿来轰炸邮箱，同一个账号一天最多发 5 封，同一个地址 10 分钟内只发一封。
- **设置里可以改邮箱。** 「设置 → 账号 → 邮箱」显示当前的地址，填新地址后同样发确认信，点链接后才换过去；确认之前信照旧发到原来的地址。以后重新用 GitHub 登录也不会把它改掉。
- **登录时不再向 GitHub 要邮箱权限。** 既然每个地址都要自己确认，GitHub 那边的邮箱就用不上了，所以登录同意页上少了一项权限，只读公开资料。
- 申请页去掉了「接收结果的邮箱」一栏，回到「一句话 + 提交」；提交后会写明通过后邮件发到哪个地址（打码显示）。

兼容性：数据库迁移 012（新增 `contact_emails`、`email_confirmations` 两张表；已有的邮箱地址会搬过去，但都算作未确认）。无新增环境变量；门只在配置了邮件（`WANCTL_SMTP_*` 和 `WANCTL_MAIL_FROM`）且用 GitHub 登录的实例上生效。门户和 relay 需要一起升级（同一个镜像，照常发版即可）。只用命令行、不打开门户的用户不受影响。
