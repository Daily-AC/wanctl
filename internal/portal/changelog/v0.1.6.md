# v0.1.6

这一版修的是同一个坑的两半：**重装过的设备，会从门户上彻底消失，而且没有任何按钮能把它找回来。**

## 设备在线，点进去却连不上

门户第一次连一台设备时，会把它的身份指纹记下来。之后指纹对不上就拒绝连接——这是防止有人冒充你的设备，本身是对的。

问题是「对不上」之后没有出路。页面只会说「连不上这台设备，可能它不在线」，而列表里它明明是在线的；新旧指纹一个都不给你看，也没有地方点头确认。更麻烦的是，把设备解绑再重新纳管也没用：解绑只删了中继那边的记录，门户记住的那条指纹原封不动，于是同名设备重装多少次都撞同一堵墙。

现在：指纹对不上时，页面会给你一张卡片，把**门户记住的**和**设备现在报出的**两个指纹并排列出来。确认是你自己重装的，点一下就恢复了。

要提醒一句：如果你并没有重装过那台机器，指纹变化就是要当成安全事件来查的信号，别顺手点接受。

另外，解绑设备现在会一并忘掉记住的指纹——解绑本来就是你在说「这个名字不再指那台机器了」。

## 装完的设备，门户从一开始就连不进去

设备只认「门户管理员」名单里的身份，名单空的时候一律拒绝。而这份名单以前没有任何环节会自动填：装机不填，授权也不填，只能靠手工传 `--portal-fps`。所以一台新装的设备，网页控制台其实一直是连不上的，只是大多数时候被顺手补上的参数掩盖着；一旦清过设备的配置目录，它又会悄悄回到这个状态。

现在授权（在终端里跑 `wanctl` 贴 code 那一步）会自动把门户身份种进去。终端会打印它信任了哪个指纹，授权网页上也显示同一个值——**请核对这两个是否一致**，因为这个值是经中继送到设备的。

**已经装好的设备不会自动补上**，需要重新授权一次，或者手工执行 `wanctl portal-admins add <指纹>`（注意要用 agent 实际在跑的那个账户来执行）。

## 审批卡片上的「影响」一行，从来就没显示过

一条待审批的操作会告诉你它的影响是什么（执行命令 / 写入删除文件 / 读取内容），这行字被一条全局样式规则藏起来了，历史上任何一个版本都没显示过。现在能看见了。

## 顺带

门户的小盾牌换成了透明背景，头部和加载页不再是一张浮在奶油色上的白卡片。
