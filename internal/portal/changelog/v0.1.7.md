# v0.1.7

**安卓手机和平板现在可以当作被控设备了。** 这是第一个带 `android/arm64` 安装包的版本，也就是说，从这一版起手机能自己装、自己升级。

已经在一台 vivo 平板（Android 13）和 Android 16 模拟器上，经生产中继完整跑通：远程执行命令、输出实时回传、退出码正确、文件双向传输内容一致。安卓有两种用法——插着数据线用 `adb`，或者在手机上开一个 Termux 终端——两种都验过，因为它们的坑不一样。

## 安卓上都能做什么

和控制一台 Linux 机器没有区别：`wanctl exec` 跑命令、`wanctl push` / `wanctl pull` 传文件、`wanctl logs` 看这台设备上发生过什么。会话里能用手机上已经装好的工具（比如 Termux 里的 git、Python）。

几个安卓特有的事情，用之前值得知道：

- **文件往哪放。** 安卓上绝大多数目录是写不进去的。传文件请用 `/data/local/tmp`，或者 Termux 的主目录。传到别处会得到一个权限错误——那是安卓在拒绝，不是 wanctl 出问题。
- **设备叫什么名字。** 所有安卓设备的主机名都是 `localhost`，拿它当设备名既看不出是谁、两台手机还会打架。现在默认改用手机的型号，比如那台平板就叫 `pa2353`。同型号的两台仍会重名，用 `--name` 自己起一个。
- **域名解析。** 安卓没有常规 Linux 的域名解析配置，wanctl 在安卓上会使用自带的公共 DNS。如果你的中继在公司内网、走的是内部域名，需要显式告诉它用哪台 DNS：`export WANCTL_DNS=10.0.0.53`。
- **后台能撑多久。** 安卓不允许普通应用注册开机自启的后台服务，所以 `wanctl service install` 在安卓上会直接告诉你装不了，而不是假装装好了。`wanctl start` 起的后台 agent 能扛住息屏锁屏（实测 25 分钟没掉线），但**重启手机就没了**，需要手动再起一次。

## 一个和安卓无关、但值得说的修复

**设备的权限模式，重启后会悄悄变回去。**

如果你把一台设备切到了 bypass（全放行）模式——不管是命令行切的还是在门户网页上切的——它本该一直保持这个状态。文档也是这么写的，`service install` 特意不写死模式，就是为了让你在门户上的切换能活过重启。

但实际上程序在启动时把它覆盖成了默认的 normal，那条"沿用上次模式"的逻辑从来没被执行过。于是设备每次重启都悄悄退回 normal，而命令行的说明还在告诉你它会保持。

现在修好了。**注意**：这意味着以前被切到 bypass 的设备，从这一版起重启后会**真的**保持 bypass。如果某台设备你并不想让它一直全放行，明确设一次：`wanctl agent --mode normal`，或者在门户上切回去。
