## 设备别名

- 设备的拥有者可以给它起一个自己看得懂的名字。别名在门户里到处都显示——设备卡片、设备页标题、两种待办卡片——机器自己的名字始终并排跟在旁边。别名是更好用的把手，不是伪装：安全控制台不该让你看不出面前是哪一台机器。

- 别名同样可以当 `--target` 用：

  ```bash
  wanctl exec --target 客厅 "uname -s"
  ```

  `wanctl peers` 打印成 `name  (alias)`，MCP 的 peers 工具也带上这份映射。真名永远优先于别名。

- 在设备的设置页（齿轮）里一行填写，清空保存即删除。别名 1 到 40 个字符、不能含斜杠，不能与另一台设备的别名或任何设备的真名重复；被拒时门户给出一句话说明。

- 别名只是显示与寻址，不是改名。设备上报的名字、指纹绑定的名字、活动日志记录的名字都不变。控制端在身份 pin 之前先把别名解析回真名，所以第一次用别名连接不会重新问一遍这台机器已经确认过的指纹。

## 通知

- 新增账号级 webhook 通知，支持飞书群机器人、钉钉群机器人，以及任意 JSON 接收端。一个账号一个目的地，每台自己的设备一个默认关闭的开关，都在门户的设置里配置。

- 覆盖四类事件：审批、命令执行、上下线与注册、安全（配对与信任变更）。命令执行默认只在失败时通知。

- 所有外发请求都由 relay 发出。设备把事件报给 relay，relay 统一投递，于是整个部署只有一个限流器、一份投递健康记录、一个源 IP——机器人的 IP 白名单只需要填这一个。设备也不必为此新开一条通往飞书或钉钉的出网路径，webhook URL 和签名密钥从不离开 relay。

- 默认不带明细。`include_detail` 关闭时，设备在序列化之前就把命令行、文件路径和对端文本剥掉，只留事件 ID、类型、时间和退出状态。

- 目的地必须是 HTTPS，由服务端强制；relay 出网拒绝私有地址段。共享设备的被授权方读不到 URL、密钥和投递健康。门户里的「发送测试通知」会把接收端的 HTTP 状态码和 provider 返回码原样显示出来——飞书和钉钉拒收时同样返回 200，只看状态行是看不出来的。

## 设备端

- Windows 上 `wanctl exec` 不再每执行一次就闪一个控制台窗口。agent 是分离启动的、自己不拥有控制台，它拉起的每个控制台程序因此都会新分配一个带可见窗口的控制台；在交互式桌面会话里，那就是每条命令一次闪烁。现在持久会话 shell、一次性 shell，以及取消时用的 `taskkill` 都以隐藏窗口启动，长期挂着的那个会话 shell 也不再留窗口在桌面上。

## 门户

- 首页就是设备，其余全部收进齿轮。设备详情从五个标签收到三个（待办 / 信任与规则 / 活动），执行模式提到标题行。

- 设备列表上方是所有设备上等你决定的事，跨设备汇总。产品的主张是没有你点头就什么都不跑，那么第一屏该回答的就是有没有人在等你，而不是你有几台机器。没有人等待时这一块完全不渲染。共享给你的设备不在其中：ACL 授权给的是使用权，不是替对方审批的权利。

- 有登录页了。此前匿名访问会被直接弹到 github.com——你在没见过这个产品任何一个界面的情况下被要求授权 OAuth 应用，而「本实例仅限邀请」是授权之后的下一页才告诉你的。现在页面先写明实例、先说仅限邀请、并说明不索取任何 GitHub 权限。等待邀请页也终于有了退出的路，用错账号登录不再是死胡同。

- 手机上的设置分成两级：列表一屏，点进去是该节一屏，返回有箭头。两级都在 URL 里，系统返回键可用，链接分享出去落在发出时的那一屏。

- 手机上做了一轮全量走查，每个可达状态 × 7 种视口 × 两种语言逐一测量。页面横向溢出、对话框跑出屏幕或偏心、文字被截断、只能横向滚动才读得到的内容，全部归零；触控目标做到 40×40。指纹不再被截到 30 个字符还不给省略号，而是完整显示；窄屏上的表格改成堆叠。

- 头像回来了。GitHub 头像叠在字母徽章之上，加载成功才显示；缺失、加载失败和 SSO 模式都停在同一个字母上，位置不动。
