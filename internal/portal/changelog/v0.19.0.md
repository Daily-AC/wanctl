# v0.19.0 — 托管 MCP 只用 OAuth，设备掉线不再卡住命令

- **公网 MCP 端点只支持 OAuth 登录。** 不带 OAuth 凭证访问 `/mcp`（或 `/wanctl-mcp`）的请求，现在会收到 401，并附带让客户端自动发起授权的提示。以前不用 OAuth 也能进来的旧办法已经删除，也就是先调 `wanctl_login` 拿一次性码、再用 `wrb1.` 开头的凭证续登。**为什么：** 这条旧路的「退出登录」只记在 relay 的内存里，relay 一重启，已经退出的凭证又能用了。**受影响的人：** 在 ChatGPT、claude.ai 里按 OAuth 接入的连接器不受影响。Claude Code 里靠一次性码登录的 HTTP 条目会显示一次「Needs authentication」，在 `/mcp` 里点授权即可。不支持 OAuth 的第三方托管 AI 用不了公网端点了，请改用本机的 `wanctl mcp`（stdio 方式，没有变化）。
- **设备掉线或重启时，正在跑的命令会马上结束，不会一直卡住。** 以前设备上的 agent 被杀掉，或者自动更新换了进程，控制端的 `wanctl exec` 会一直等下去，Claude Code 这类 AI 工具的调用也跟着卡死。现在 relay 发现设备掉线后就会结束这条会话：设备自己重启时几秒内结束，设备直接断开时大约 20 秒内结束。控制端会退出并返回非 0，提示 `device disconnected: its agent went offline or restarted mid-session`。设备只是短暂断网、agent 进程还在的时候，不受影响。
- **运营方可以停用一个账号。** 被停用的账号：命令行和设备令牌、OAuth 授权、WebFetch 授权都立即失效，正在进行的会话会断开，设备会掉线，门户会显示「此账号已停用」，重新用 GitHub 登录也进不来。恢复启用后，一切照旧，设备不用重新登记就会自动连回来。

兼容性：数据库迁移 013（`users` 表新增 `disabled_at` 列）。门户和 relay 需要一起升级。第二条的修复在 relay 上，各版本的设备和控制端都会受益；要看到「device disconnected」这句提示，控制端需要升级到 v0.19.0，旧版本只会显示连接结束。自建实例：公网 MCP 端点从此必须配好门户，也就是数据库、`WANCTL_PUBLIC_ORIGIN` 和 `WANCTL_PORTAL` 都要有，否则 `/mcp` 返回 503 并说明缺了哪一项。`wanctl mcp --http` 和容器角色 `WANCTL_ROLE=mcp` 已删除，它们的登录方式只有被删的那条旧路。
