# v0.21.0 — agent 能操作 Windows 桌面了

- **新命令 `wanctl act`（MCP 工具 `wanctl_act`）。** agent 先截一张图，再按图上的坐标在 Windows 设备上点击、拖动、滚轮、打字、按键，切到某个窗口，或者启动程序（可以直接用桌面快捷方式 `.lnk`）。一次调用是一批按顺序执行的动作，最多 64 个。坐标按截图像素给，换算成物理像素由设备完成，缩放屏、多显示器都按实际位置落点。截图和动作之间窗口变了、被盖住了，或者截图超过两分钟，这一批就拒绝执行，要重新截图。
- **和 exec 走同一道审批。** 设备跑普通模式时，`act` 和 exec 一样要审批，审批卡上只显示动作类型（比如 `act click,type`），不显示要打的字；放飞模式自动放行。活动日志、通知里也只记字符数（比如 `type(26 characters)`），打字内容不落盘。
- **屏幕上有提示，人一动就停。** 操作进行时，屏幕顶部有一条「正在操作这台电脑」的提示条，带停止按钮。电脑前的人一动鼠标或键盘，这一批立刻停下（光影精灵上实测 20 毫秒以内），返回「有人在用这台电脑」，不会残留按住的键；agent 要先问人，不会自己重试。别的程序发出的模拟输入也一样会让它停，只有 `act` 启动的程序在启动过程中自己发的模拟按键例外。
- **截图带上了操作需要的信息。** Windows 上的 `wanctl screenshot` 现在返回设备端缩小后的 JPEG（长边最多 1280 像素）和一个截图编号，附带缩放比、各显示器的位置和 DPI、前台窗口，以及可见窗口列表。锁屏、安全桌面或 agent 不在用户桌面会话里时，返回明确的错误，不再给一张空白图。
- **控制端断了，设备上没做完的操作就取消。** 控制端进程被杀或网络断开时，relay 约 2 秒后通知设备，`act` 里还没执行的动作不再执行。默认的 HTTP 传输以前要很久才让设备知道控制端断了。

只支持在用户桌面会话里运行的 agent（Windows 10 2004 及以上）。以 Windows 服务方式安装、跑在会话 0 里的 agent 还不能截图和操作桌面。

已知限制：
- 打字过程中如果别的程序突然抢到前台，最多可能有 1 个字落进那个窗口，随后立刻停下并报错，不会继续打。
- 以管理员权限运行的窗口在前台时，`act` 切不走它，也不会对它点击或打字。遇到这种情况要请电脑前的人先切开。

兼容性：relay 和设备都要升级到 v0.21.0；控制端断开的改进在 relay 里，旧版控制端也受益。Windows 截图的返回格式变了（JPEG 加截图编号和窗口信息）。无数据库迁移，无新增环境变量。
