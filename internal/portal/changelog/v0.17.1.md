# v0.17.1 — 取消命令不留尾巴，下行传输少压一块内存

- **持久会话里取消命令更干净。** 三处修复，来自 [@team-humaki](https://github.com/team-humaki) 的 #113、#116、#117，合并成 #139：
  - 取消一条正在往 shell 写入长命令的操作时，现在连 shell 的输入一起切断。以前 shell 已经不读输入、终止进程又失败时，这次写入会一直卡住。
  - shell 自己退出时，它留在后台的任务（比如 `sleep 600 &` 之后 `exit`）会一起结束。以前这些任务会一直活着。
  - shell 退出后，系统一回收它就结束整组进程，不再等输出管道收尾（以前最多要多等 2 秒）。
- **下行传输读完一块数据就释放它。** 以前这块数据要等下一块到了才释放，每条连接最多多占一块（最大 16 MiB）。
- **文档。** 新增一篇「让 wanctl 快起来：代理、大文件和自查」：用了代理时让 relay 走直连、大文件怎么传、慢的时候怎么查。Windows 安装页加了一节：agent 以 SYSTEM 身份运行时，怎样按登录用户的身份跑一条命令（比如只装给当前用户的安装器），输出和退出码照常带回（#131）。

无需任何操作。无数据库迁移，无新增环境变量。
