# v0.3.4

**自建部署分发的安装脚本，现在会从这台 relay 自己安装。**

面向连不上 GitHub 的网络。官方 GitHub 发布页的安装方式完全不变，从那里拿到的脚本行为也不变。

## 安装

- relay 的 `/install.sh` 和 `/install.ps1` 现在会被改写成从这台 relay 自己的 `/dl` 镜像下载，不用再额外指定任何环境变量：

  ```bash
  curl -fsSL https://relay.example.com/install.sh | sh
  ```
  ```powershell
  irm https://relay.example.com/install.ps1 | iex
  ```

  在此之前，relay 分发的是发布构建烘焙好的那份脚本，它的下载地址指向 GitHub 发布页——而会来 relay 取脚本的人，往往正是访问不了那个页面的人：脚本下得到，第一次下载却卡住。

  改写取自 `WANCTL_PUBLIC_ORIGIN`，绝不采用请求头里的 Host，官方 Compose 已经包含该变量。`WANCTL_RELAY` 和 `WANCTL_DIST_BASE` 仍然优先于它。

## 升级

- 新增 `wanctl config set release_base=…`，指定 `wanctl update` 从哪里获取已签名的发布件：

  ```bash
  wanctl config set release_base=https://relay.example.com/dl
  ```

  从镜像装好的二进制，此前升级时仍会回到构建时烘焙的发布页，只能每次调用都带一遍 `WANCTL_RELEASE_BASE`。该配置项此前只读取环境变量和编译期默认值，跳过了其余设置都会经过的配置文件层，现在与 relay / portal / transport 一致：命令行 > 环境变量 > 配置文件 > 编译期默认值。
