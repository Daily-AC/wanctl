# v0.24.0 — `wanctl act` 接上 OpenCU：读懂窗口里的控件，按编号操作

- **`wanctl act` 新增 OpenCU 模式。** Windows 设备装了 [OpenCU](https://github.com/Daily-AC/opencu)（独立的开源 computer-use 引擎）后，agent 先用 `act --discover` 查它提供哪些工具，再用 `--tool` 和 `--arguments` 按名字调用：读出应用窗口里的控件（按钮、输入框、网页链接）和窗口截图，再按编号点击，或者打字、按键、拖拽、滚动。wanctl 只把调用原样转给设备上的 OpenCU，不内置它的工具列表；OpenCU 以后加工具，wanctl 不用升级。原来的 `actions` 模式保持不变。
- **没装 OpenCU 时，act 会告诉你怎么装。** 返回 `OPENCU_NOT_INSTALLED`，附一行安装命令，在那台电脑的 PowerShell 里运行即可，不需要管理员；`actions` 模式照常可用。
- **同一个控制端在同一台设备上共用一条 OpenCU 连接。** 多次调用之间保留控件编号和截图坐标；10 分钟没有调用就关闭，agent 退出或自动更新前也会关闭。多个对话共用同一身份时，一个对话的观察可能让另一个对话的编号失效，这时重新观察即可。
- **有人按 Esc 停止后，必须本人重新批准。** OpenCU 报告 `USER_STOPPED` 后，这台设备上该控制端的 OpenCU 调用全部拒绝（`OPENCU_STOPPED`）；下一次调用即使设备是 bypass 模式或有保存的规则，也要本人批准，批准后才开新连接。有人正在用键盘鼠标时返回 `PERSON_ACTIVE`，agent 要先问人，不会自动重试。
- **命令行把截图存成文件。** OpenCU 返回的每张截图存成 PNG 并打印路径，靠 shell 驱动的 agent 可以直接读图；`-o -` 输出完整的原始结果。
- **两种装法都支持。** 登录用户计划任务装的 agent 直接在桌面会话里启动 OpenCU；以 SYSTEM 跑在会话 0 的装法，会在当前登录用户的桌面会话里、以该用户的普通权限启动 OpenCU。审计日志只记 `opencu <工具> <应用>`，不记输入的文字、粘贴的内容和截图。
- **设备推送时 `status` 不再被第一块数据堵住。** 设备读取传输的第一块数据以前可能在心跳和握手走的那条连接上占用最多 2 MiB；限速 400 KB/s 时，推送开始 1 秒后的 `status` 要 7.5 秒。现在这一块最多 256 KiB，同样场景约 1.2 秒。代价是 256 KiB 到 1 MiB 的推送多一次往返，约 0.1 秒。

兼容性：OpenCU 模式需要控制端和设备 agent 都升级到 v0.24.0，设备上另装 OpenCU v0.3.0 或更新；老版本 agent 收到 OpenCU 请求会报不支持，`actions` 模式不受影响。推送那一条只需要升级设备 agent。新旧版本可以混用，无数据库迁移，无新增环境变量。
