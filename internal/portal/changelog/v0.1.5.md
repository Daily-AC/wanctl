# v0.1.5

这一版修的三件事有个共同点：出问题的时候它们都不吭声，甚至还告诉你一切正常。

## 审批模式关掉 bypass 后，仍然全部自动放行

如果一台设备是带着「放飞模式」启动的，之后你在门户上把放飞关掉，**它其实还在放飞**——每条命令照样自动执行，而活动日志里记的是「已批准」，看起来就像有人真的点过同意。

原因是审批器在设备启动那一刻就按启动参数定死了，门户后来改的是另一个开关。现在审批器不再被启动参数绑定，模式随时切换都立刻生效。

**你可能受影响**：任何用 `--mode bypass` 启动、后来在门户关掉放飞的设备。升级后重启一次就好。想确认历史记录的话，真正经过人工审批的那条前面一定跟着一条「远程决策」记录，只有「已批准」而没有它的，就是这个 bug 放行的。

## 装完服务后，门户点「信任」得到一个 502

`wanctl service install` 生成的开机自启配置只写了「运行 agent」，没带上设备名，也没带门户的身份指纹。没有指纹，设备就不认门户，门户自然连不进来——你在浏览器里点信任，只会收到一个没有任何解释的 502。设备名也会悄悄退回成主机名。

现在这两项都能写进自启配置：

```
wanctl service install --name 我的设备 --portal-fps SHA256:...
```

没提供指纹、设备上也还没有的时候，安装会直接把这个后果说出来，而不是等你在浏览器里撞上 502。

## 飞书卡片上的「在门户查看完整上下文」点不动

那个按钮带的是一个相对地址，而飞书客户端里没有网址可以拼接，于是点了就是没反应。现在它总是完整地址。
