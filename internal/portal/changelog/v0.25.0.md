# v0.25.0 — MCP 省 token：工具说明减半，结果只回紧凑文本，命令跑完再返回

- **工具清单从约 18,400 token 降到约 8,500。** 一次加载全部工具的客户端（ChatGPT、claude.ai、Codex、Cursor 等）每轮请求都带着这份清单。以前同一条规则在每个工具里各写一遍：配对链接怎么处理、首次接触怎么确认设备身份、先读 AGENTS.md、workspace 模式、安卓 adb 排障。现在每条规则只放一处：挑工具、填参数时要用的写在工具说明里；出错时才用的放在那条错误返回里，配对、首次接触和身份不符的返回本来就写全了，adb 排障改为报错时附上；会话开始读一次的放在 instructions 里。instructions 不再重复列出全部工具，从约 970 token 降到约 460。
- **结果只回紧凑文本，不再带 structuredContent 和 outputSchema。** Claude Code 和 Codex 在两者都有时只把 structuredContent 的 JSON 交给模型，文件内容和命令输出被转义成 `\n`、`\"`，读代码多花 20–25%，每条 workspace 命令还多带约 235 token 的字段。现在所有客户端拿到同一份文本：一条短 exec 从约 90 token 降到 20 以内，一条短 workspace 命令从约 220 降到约 40。
- **MCP 撤掉 4 个工具：wanctl_id、wanctl_trust、wanctl_rules、wanctl_server_logs。** 控制端指纹看 wanctl_status，设备身份有没有确认过看 wanctl_peers；策略规则和服务端日志是设备主人和运维看的，远程驱动的 AI 用不上。命令行的 `wanctl id`、`wanctl trust`、`wanctl rules`、`wanctl logs --service` 不变。托管端点也不再列出在那里只会报错的 wanctl_push 和 wanctl_pull。
- **命令跑完再返回。** workspace 里的 exec 和 exec_poll 最多等 20 秒，命令在这期间结束就直接带着结果返回，不用再轮询；没结束就返回已有输出和 next_offset。同一组典型开发操作实测，工具调用从 19 次降到 15 次。
- **单次读取和 workspace 输出都有上限。** wanctl_read 每次最多返回 48 KiB（以前 256 KiB，约 7 万 token），截断时给出续读的 offset。workspace 命令输出超过 48 KiB 时返回开头和结尾两段，中间注明跳过了多少字节、从哪个 offset 接着读；以前要一页一页读完。命令行 `wanctl read` 仍是 256 KiB。
- **老版本设备收到 act 的 OpenCU 请求时，提示升级设备 agent**，不再报一个看不懂的截图错误。

兼容性：只需升级控制端，也就是本机的 `wanctl mcp` 或托管 relay，设备 agent 不用升级。程序化读取 structuredContent 的调用方要改为读文本。无数据库迁移，无新增环境变量。
