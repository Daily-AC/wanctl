# v0.1.13

**这一版只做了一件事：让安卓手机上的 `wanctl exec` 能干 `adb shell` 能干的事。**

在这之前，命令都跑在应用沙箱里。`pm`、`am`、`input`、`screencap`、`dumpsys`、`settings`、`wm`、`svc`——安卓上真正有用的那一半——全都够不着。这不是少写了几个功能：`adb shell` 是 uid 2000、`shell` 权限域，而 agent 是普通应用 uid、`untrusted_app` 域。上一版查电量之所以要绕道 Java 采集，就是这条线卡的。而绕道这招不能推广，因为 adb 的大部分能力在应用这一侧根本没有对应接口。

所以这一版没有加一堆命令，只加了**一条提权通道**——通了之后，整个 adb 命令面自然就到手了。

## 用法

```
wanctl exec -target 手机 --elevate -- pm list packages -3
wanctl exec -target 手机 --elevate --via su -- dumpsys battery
```

两条通道，按顺序探测，谁可用用谁：

| 通道 | 需要什么 | 重启后还在吗 |
|---|---|---|
| `su` | 已 root 的设备 | **在** |
| `adb` | 开发者选项 → 无线调试 | 不在——安卓开机会关掉它 |

`--via` 可以点名一条。**点名了但那条不可用，会直接报错，不会偷偷降级去跑**——你要的是 root，结果它悄悄用普通权限跑完了，那是一个披着正确外衣的错误答案。

只有 `su` 能在没人碰设备的情况下一直可用。要求断电重启后仍然可控的手机，要么 root，要么不要依赖提权。这是安卓的规矩，不是我们能绕开的，所以写在这里而不是等你自己撞上。

## 没 root、没数据线也能用

在没 root 的手机上，agent 自己变成一个 adb 客户端，连自己的 adbd。打开**无线调试**，配对一次：

```
wanctl exec -target 手机 -- adb-pair 41439 891268
```

端口和六位数字来自：设置 → 开发者选项 → 无线调试 → **使用配对码配对设备**。那个界面上有两个端口，它们不是同一个监听，要用配对码旁边的那个——连错端口是"连接被拒绝"最常见的原因。

配对命令跑在**设备上**，因为只有设备自己够得着它的 adbd 打开的那个配对端口；它也不需要提权，否则就成了"要提权才能开通提权"的死循环。

配对是安卓 11 引入的 SPAKE2 交换，这一版从零实现了它（AOSP 用的是 BoringSSL 那个基于 Ed25519 的变种，和公开标准不是一回事，Go 生态里没有现成实现）。它和系统真的对得上——配对完成后，设备自己的**已配对的设备**列表里会出现 `wanctl@<设备名>`。

配对是持久的，重启还在。无线调试本身不持久，重启后开关要重新打开，但**配对码不用再输一次**。

**端口不用你填。** 安卓每次打开无线调试都会换一个端口，而且只通过局域网广播公布——实测在同一台手机上，重新配对一次端口就从 37819 变成了 41031。App 会自己监听并把端口交给 agent，并且只认本机自己的广播：同一个 Wi-Fi 下每台开了无线调试的手机都在广播同一种服务，所以会先核对地址是不是本机的，再决定信不信。

## 提权命令是单独一类

**「自动放行所有命令」不覆盖提权命令。** 那个开关的意思是"这台设备没人守着，普通命令别拦"，不能顺带把 root 也发出去。在开了自动放行的设备上，提权命令仍然需要一条明确的规则或一次人工批准；普通 `exec` 的规则也不会自动授权同一条命令的提权版本。

App 里有独立的**提权通道**开关，默认关，升级之后也还是关——不会因为有人装了新版本，设备就突然变得更有权限。开关关着的时候，通道根本不探测、端口也不监听。

每一条提权命令都会带着"用哪条通道跑的"写进设备日志，所以 `wanctl logs` 能回答**这台手机上都有谁以 root 跑过什么**。

## 顺手好用的几条

```
wanctl screenshot 手机 -o shot.png        # 自动提权；-o - 直接输出到标准输出
wanctl exec -target 手机 --elevate -- input tap 540 1200
wanctl exec -target 手机 --elevate -- app list -3
wanctl exec -target 手机 --elevate -- settings get global adb_wifi_enabled
wanctl exec -target 手机 --elevate -- logcat -f
```

## 有一步必须人来做，一次

第一次连一个还没配对过的 adbd 时，手机会弹**允许 USB 调试吗？**并显示 wanctl 的密钥指纹。这一步软件替不了：用 `input tap` 去点它会被系统拒绝（缺 `INJECT_EVENTS` 权限）——这正是设计使然，如果程序能点这个按钮，那任何程序都能给自己开 shell 权限。

要批量铺设备的话，提前把这一步算进去。

## 升级说明

协议只增加了两个可选字段，不用提权的控制端和以前完全一样，所以**控制端和设备可以各自升级、顺序随意**。

唯一要注意的情况：拿新控制端对**旧 agent** 用 `--elevate`，旧 agent 不认识那个字段，会按普通权限把命令跑掉。控制端能识别出这种回应并报为失败，同时告诉你命令**已经执行过了**——这话是故意说出来的，免得你直接重试一遍。

提权本身需要手机上装新版 App，并且打开提权通道开关，再加上 root 或一次配对。没有任何东西会自己打开。
