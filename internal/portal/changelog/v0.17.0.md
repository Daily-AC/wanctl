# v0.17.0 — 申请页只剩一扇门，邀请绑定 GitHub 用户名

- **申请页重做。** 用 GitHub 登录、还没被放行的人落在这一页。以前页面上有两张表单：上面兑换邀请码，下面申请访问，中间一条线隔开。现在只剩申请：你的 GitHub 头像、一句说明、一栏给管理员的话、一个「提交申请」按钮。提交后这一页显示申请走到了哪一步；配了邮件的实例会说明通过后信会寄到哪个邮箱（打码显示）。输入框改成 16px 字，iPhone 上点进去不会再整页放大。
- **不再有一次性邀请码。** 管理员在「邀请」页填对方的 GitHub 用户名发出邀请，对方用这个账号登录就直接进来，不用传任何码；批准一份申请也是同样的效果。`wanctl admin invite` 现在必须带 `--github LOGIN`。以前生成、还没用掉的邀请码不能再兑换，「邀请」页把它们标成「邀请码（已停用）」，撤销即可。
- **管理员的「邀请」页：申请收成一行入口。** 有人在等时，标题下面出现一行「访问申请 · N 个待处理」，点开才是申请卡片；没人等时这一行不出现。以前卡片直接压在「邀请」标题上面。
- **申请通过的邮件改成 HTML。** 主题更短，正文只有一句说明和一个「登录」按钮，门户网址只出现一次；同时附一份纯文本版，给不显示 HTML 的邮件客户端。
- 修了一处小问题：管理员给邀请填了格式不对的 GitHub 用户名时，relay 以前返回 500，现在返回 400。

兼容性：无数据库迁移，无新增环境变量。门户和 relay 需要一起升级（同一个镜像，照常发版即可）。自部署文档里开第二个用户的命令改成了 `wanctl admin invite --github LOGIN`。
