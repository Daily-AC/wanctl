# v0.12.0 — CLI 和 MCP 共用持久化远程工作区

- **远程工作可以跨工具调用继续。** `wanctl workspace enter` 创建由设备持有的独立 shell，`attach` 恢复工作区，`status` 查看状态，`exit` 显式关闭。工作目录、环境变量和命令结果留在该工作区；短暂断连只停止控制端等待，已经提交的任务继续运行。重连后用原来的请求 ID 读取结果，重复提交同一个请求不会再次执行。
- **CLI、本地 AI 和网页 MCP 都能使用工作区。** CLI 的 exec/read/write/edit 支持 `--workspace` 或 `WANCTL_WORKSPACE`；专用 stdio 进程可用 `wanctl mcp --workspace-session` 自动绑定。共享 HTTP MCP 使用显式工作区引用，避免同一 OAuth 账号的多个聊天互相改变当前目录。CLI 与本地 MCP 使用同一控制端身份时可以接续工作；网页 OAuth 控制端的身份独立，不能仅凭同一个账号接管本地 CLI 的工作区。
- **长任务可以提交、轮询和取消。** `wanctl exec --async --request-id ...` 提交后返回，`wanctl workspace poll` 继续读结果；`cancel` 停止命令并关闭对应 shell。匹配 shell 的 sh/PowerShell 脚本直接在工作区内执行，脚本里的目录和环境变量改动会保留。普通 Python 程序也能从 shell 调用，但本版不提供持久化 Python 内核、交互式终端或端口转发。
- **连接复用仍逐次检查授权。** 已授权连接的复用会重新核对设备信任和原始凭证或分享权限；权限撤回后不能继续复用。MCP 的首次信任说明尊重宿主确认流程，不再要求 AI 跳过询问。OAuth 下首次调用身份工具也会正确初始化控制端身份。
- **安装和登录后说明下一步。** 安装器与 `wanctl login` 明确区分：`login` 只登录，`start` 让本机作为受控设备上线，`service install` 由系统管理受控服务。完整命令继续以 `wanctl help` 和统一命令文档为准。

本版已在本地 Codex 的 CLI/stdio MCP 和 ChatGPT 网页 MCP 中完成真实开发任务、工作区隔离、结果重取、重复请求和显式退出验证。

使用完整工作区能力需要同时升级控制端、relay 和受控端。无数据库迁移；原有命令保持兼容。打开的工作区会阻止设备自动更新，完成任务后请显式退出。工作区状态存于设备进程内，可跨网络重连，但不跨 agent 重启持久保存。架构及使用说明见 `docs/workspaces.md`，系统架构教学见 `docs/learning/remote-workspace/`。
