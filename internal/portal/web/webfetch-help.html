WebFetch quick reference

Use your URL-reading tool for every step: authorization status, tool calls and results are all GET requests. exec is a query parameter, not a separate connector.

Already authorized? Call a tool

  1. GET the full status_url from your current conversation. If status is approved, copy call_endpoint, the selected tools[].call_url_template and a devices[].target value exactly. Keep these full URLs in your reply for later turns.
  2. Fill the template with the task the user requested. URL-encode each parameter value once. target must be the full namespace/device_id, with its slash encoded as %2F. rid is a new operation ID: 1–64 letters, digits, hyphens or underscores.
  3. GET the completed URL using the same URL-reading tool. No POST, browser login cookie, Authorization header, Python or MCP is required. Reuse the same rid and arguments if that request must be retried.

Syntax only — CALL_ENDPOINT comes from the approved status response. Replace all placeholders before fetching; never invent a ticket or execute an example automatically.

GET CALL_ENDPOINT?rid={rid}&tool=exec&target={target}&command={command}

Encoding example: the command ls -la becomes command=ls%20-la. Optional exec parameters: cwd and timeout_seconds (1–60, default 30).

Read the actual result

The call returns job_id and result_url. GET result_url, then follow next_url while running (at most 8 polls). done includes result; for exec report stdout, stderr and exit_code. failed is an error; unknown must not be retried automatically because the operation may have run. A loaded HTML page is not proof of success: always check status and http_status. Add format=json for programmatic clients.

If result.error_code is pairing_required and execution_started is false, give pairing_url and continuation_prompt to the owner. After the owner confirms device pairing, retry the requested operation with a NEW rid; the previous failed job stays failed. Device permission rules still apply. If authorization expires or is revoked, stop and report it.

Start a new conversation

The owner copies a fresh prompt from Connect web AI. GET that URL, return approval_url and the complete continuation_prompt, then wait for the owner to approve. Read status_url after approval. Keep the current session for later tasks; do not create a new authorization for each command. Only the owner approves access and pairing.
