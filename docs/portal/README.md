# 门户使用文档的真源

`https://portal.example.com/#docs` 上那些文章的正文就在这个目录里。门户只是渲染层，改文档改这里，然后同步上去：

```sh
wanctl login                      # 需要一个已登录的控制端身份
scripts/sync-portal-docs.py       # 幂等：已有的更新，缺的新建
scripts/sync-portal-docs.py --dry-run   # 先看它打算做什么
```

`manifest.json` 定义分组、标题、排序和文件映射；正文是同目录下的 markdown，文件名规则 `<组 slug>__<文章 slug>.md`。

## 为什么要有这一层

门户文档原本只活在 relay 的 Postgres 里。2026-07-16 托管平台控制台上误删了 relay 的 app（详情页上那个没有标签、也没有确认弹窗的红色图标按钮就是立即删除），连库一起没了。migration SQL 因为在会话记录里出现过原文，还能捞回来重灌，所以四篇 seed 活了下来；而在浏览器里手写的文章没有任何副本，**永久丢失**，直到七月底才被发现。

同一份数据 2026-07-22 迁到另一台机器上时复制过一份，但复制的已经是丢过之后的库，所以那份副本也救不回来。

结论就是这个目录存在的理由：只要正文在 git 里，库再没一次也只是重跑一遍同步脚本的事。

在浏览器里直接编辑文档仍然可以（门户有编辑功能），但那样改的内容下次同步会被这里的版本覆盖，而且不受任何备份保护。**要长期存在的内容写进这里。**
