这套部署是**邀请制**的：第一个登录的用户自动成为管理员，之后的人要被邀请才能进来。

## 邀请新用户（管理员）

导航栏的「邀请」页（只有管理员能看到）可以：

- 生成**一次性邀请码**——只在生成那一刻显示一次，发给朋友；
- 或者**预录对方的 GitHub 用户名**——对方用 GitHub 登录门户就直接进来，不用码；
- 撤销还没用掉的邀请。

被邀请的人用 GitHub 账号登录门户，有码的在提示页里兑换即可。

## 申请访问

没有邀请码的人也有一条路：用 GitHub 登录，落在等待邀请页上，点「申请访问」，可以附一行不超过 200 字的说明。

- 一个账号同时只能有一份申请在等；被拒之后要等 7 天才能再提，已获准的不再看到这张表单；
- 申请只有管理员看得见，申请人只看得见自己那一条；
- 管理员在「邀请」页看到队列，「通过」就是给这个 GitHub 用户名建一条邀请 —— 跟手动预录是同一条路，对方下次打开门户就进来了；
- 配了通知 webhook 的管理员会收到一条 `access.requested`。

## 加好友

设备和授权默认只在自己名下可见。要跨账号协作，先加好友：

- 门户「好友」页按 **GitHub 用户名精确查找**（不能模糊搜索，防止陌生人枚举用户）并发请求；
- 对方在自己的「好友」页接受后，互相可见。

## 共享设备

好友关系建立后，在「共享授权」页把某台设备共享给对方。共享不是一个降级的账号：对方在这台设备上拿到的权限和你一样。对方用 `wanctl exec --target 你的namespace/设备 …` 控制它，每一次请求仍然要过这台设备自己的模式、规则和审批——也就是你设的那一套。设备留在逐条确认，对方的命令也由你来批；设备开了 bypass，对方跟着一起放行。提权命令无论对谁都不在 bypass 覆盖范围内。

只有两件事仍然只有你能做：解绑设备，和撤销共享。

**删除好友会级联撤销双向的全部共享授权**，对方立刻失去访问。
