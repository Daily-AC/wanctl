# wanctl 的设计系统

last-reviewed: 2026-09-05

这份文件是 wanctl **三个 web 表面的唯一视觉真源**：产品官网（`site/`，部署到 wc.z10.dev）、
设备门户（`internal/portal/`）和文档站（`site/docs/`，由 `tools/docsite/build.py` 生成，
发在 wc.z10.dev/docs）。三边取同一套 token、同一套字体、同一套语法。
改视觉先改这里，再改实现。

本文**不维护**：文案正文（官网在 `site/`，门户文档在 `docs/portal/`）、
组件实现（读代码）、部署方式（见 `docs/self-hosting.md`）。

参照系统：`design-dna` 库的 `apple`。**它是参照不是法律**——专有字体和品牌色换等价物，
但它文末的 Do / Don't 是这套东西不塌掉的底线，逐条遵守。

---

## 1. 场景句

> 上午，光线很足的桌面。笔记本上一条命令刚敲下去，
> 旁边手机亮了一下——它在问你，要不要放它过去。
> 桌面是空的，白的，只有这两块屏在说话。

明暗由这句定：**浅色**。留白很多，但留白是**被布置的**，不是剩下的。

## 2. 主张

**留白中央必须有一个东西镇得住。**

「空」和「极简」的差别不在留白多少，在于中心有没有主体。
苹果的页面留白极多却从不发空，因为正中永远有一个被做到极致的主体统治那片空间。
2026-09-03 的失败版本正好是反例：几张小卡片飘在白底上，没有主体，留白就塌成了空洞。

wanctl 没有硬件可拍。**所以主体是「产品发生的那两块屏」和「被放大的真实界面」，
不是编造出来的实体。** 官网上不出现任何不存在的东西。

## 3. 色彩

**克制**：白 / 近黑 / 一个蓝。**不许有第二个强调色**（apple 的 Don't 第一条）。

前一版的安全黄已退场——它是第二个强调色，与本系统不兼容。
「等你决定」这件事改由**蓝色**和**位置**表达，不再由第二种颜色表达。

```css
--canvas:   #ffffff;   /* 主画布 */
--canvas-2: #f5f5f7;   /* 交替屏、页脚 */
--ink:      #1d1d1f;   /* 正文与标题 */
--ink-2:    #6e6e73;   /* 次级文字。白底 5.07:1，浅灰屏 4.66:1，两处都达标 */
--ink-3:    #86868b;   /* 实测 3.62:1，仅装饰，不得承载文字 */
--hairline: #d2d2d7;
--blue:     #0066cc;   /* Action Blue：一切可交互元素，且仅此一色 */
--blue-hi:  #0071e3;   /* 焦点 */
--dark:     #1d1d1f;   /* 深色整幅屏 */
--on-dark:  #f5f5f7;   /* 深色屏上的正文，15.46:1 */
--on-dark-2:#a1a1a6;   /* 深色屏上的次级文字，6.54:1 */
```

### 实测对比度（`tools/contrast.py`，算的不是估的）

工具**直接读 `site/assets/app.css` 的 `:root`**，不再抄一份色值——
LOTO 那版换了调色板但工具还在验早已下线的颜色，这种漂移只能靠取消副本来根治。
跑 `python3 tools/contrast.py`，有非预期失败就以非零码退出。

| 前景 / 背景 | 比值 | 判定 |
|---|---|---|
| `ink` / `canvas` | 16.83 | 通过 |
| `ink` / `canvas-2` | 15.46 | 通过 |
| `ink-2` / `canvas` | 5.07 | 通过 |
| `ink-2` / `canvas-2` | 4.66 | 通过 |
| `blue` / `canvas` | 5.57 | 通过 |
| `blue` / `canvas-2` | 5.11 | 通过 |
| `on-dark` / `dark` | 15.46 | 通过 |
| `on-dark-2` / `dark` | 6.54 | 通过 |
| `canvas` / `blue` | 5.57 | 通过（蓝底白字的按钮） |
| `ink-3` / `canvas` | **3.62** | **不通过，不得承载文字** |

和上一版一样的结论：**只有两档文字灰**（`ink` 与 `ink-2`）。
`ink-3` 只用于装饰笔画与分隔，任何情况下不承载文字。

## 4. 字体

SF Pro 是专有的，而 `rules.md` 禁系统字体栈当品牌字。等价物：

| 角色 | 字体 | 说明 |
|---|---|---|
| 展示 / 正文 | **Schibsted Grotesk**（可变 400–800） | 中性 grotesque，大 x-height，扛得住大字号负字距。不在禁用清单 |
| 标识符 / 命令 | **JetBrains Mono**（400 / 700） | hostname、指纹、路径、命令一律等宽 |

自托管，不走 Google Fonts（ls 在大陆，访客拉不稳）。
CJK 回退系统：`"PingFang SC","Hiragino Sans GB","Microsoft YaHei"`。

一个例外：首屏手机屏里那个 `9:41` 走系统栈（`-apple-system` …，最后才退到 Schibsted）。
它不是品牌字，是 iOS 状态栏的字 —— 那块屏在模拟一部真的 iPhone，苹果设备上看到的就该是 SF。

**苹果的字号阶不可破**（照搬，因为它是那套节奏的来源）：

- hero 展示 56px / 600 / 行高 1.07 / 字距 **-0.28px**
- 章节标题 52px / 600 / 1.06 —— 只给命题那一屏（`.tile.chapter`）
- 段落标题 40px / 600 / 1.1
- 次级段落标题 32px / 600 —— 给被压过的支撑段（`.tile.minor`）
- **正文 17px / 400 / 行高 1.47 / 字距 -0.374px**（不是 16px，多的这一像素定义阅读节奏）
- 字重梯度 300 / 400 / 600 / 700，**故意没有 500**。正文永远 400，行内强调 600。

## 5. 结构

- **整幅屏（tile）edge-to-edge，不圆角、不留槽**。浅屏接深屏，**颜色变化本身就是分隔线**，
  不需要边框、卡片或分割线。
- 内容锁 **1440px** 居中，超出的宽度全部并进左右留白。

### 权重：三档配额，不是每段都最大

2026-09-04 独立评审的第一条：整页五段的上下内边距**全是 88px**，于是产品的命题
和一张设备清单拿到完全相同的视觉配额，谁也不比谁重要——一个模板跑了五遍。

命题只有一个：**「你不点头，什么都不会跑」**，其余都是支撑。

| 档 | 是什么 | 待遇 |
|---|---|---|
| `.tile.chapter` | 命题（`#decide`） | 上下内边距 ~1.4×，标题 52px，另挂一条通栏收尾 |
| （默认） | 消解疑虑（`#private`） | 88px，标题 40px |
| `.tile.minor` | 清单（`#fleet`） | 内边距 60px，标题 32px，lead 收到 36ch |

命题那一屏的通栏收尾讲**策略语义**——规则记的是一条命令，不是一台机器。
首屏 demo 每一轮都在演它（第三条换成 `nvidia-smi` 就会重新问），
但在此之前页面上一个字都没写。两列文字撑不满 1440，这条能。

### 轴：海报居中，章节走脊

2026-09-04 之前每一屏都居中。问题不是"居中看腻了"，是**居中的标题压着左对齐的
面板**，两条轴各走各的，面板那条左缘不跟页面上任何东西对齐。同时 1440 的锁下
实际画到的最宽只有 845px（`lead` 565 / `panel` 700 / 舞台 840），
**左右各恒定空掉 275–348px**。往里塞内容是治标——那正是 09-03 触发密集恐惧症的同一条路。
治本是让布局用掉那个宽度。

| 类型 | 轴 | 为什么 |
|---|---|---|
| **海报**（首屏、安装） | 居中 | 短文案 + 单主体。居中的可读上限是 1–3 行，苹果也从不居中段落 |
| **章节**（凭证、设备表） | 左脊两栏 | 记录和表是用来扫的，扫需要固定的左缘；右半边因此成为主体可以住的地方 |
| **打断**（身份核对） | 整幅居中 | 它是两端之间的链路，不站边；顺便让两行交替不变成节拍器 |
| **并置**（两扇门） | 左脊标题 + 通栏 50/50 | 两个选择真的等价时，对称本身就是意思。而且它是第三种形状，节奏不会顺着交替一直走下去 |

主体落在左还是右**不是为了不单调，是位置在说这东西属于谁**——首屏已经定了
笔记本在左（控制端）、手机在右（你）：

- 凭证是**你**的回答 → 主体在右
- 设备表是 `wanctl peers` 的输出，**控制端**看的 → 主体在左（`.flip`）

两条纪律，缺了就滑回通用 SaaS 的之字形：

1. **文字列跑到哪边，段落自身永远左对齐。**换的是列的位置，不是文字的轴——
   右对齐段落的锯齿左缘不可读。
2. **两行的分栏比例故意不同**（42/58 与 61/39），不做镜像 50/50。

面板该不该长满自己那一栏，看它有没有东西填：凭证是五行短键值，拉宽只会在每行后面
拖出空白，所以封顶 620px 贴外缘站；设备表有右对齐的 meta 列，越宽越像一张真表，让它长满。

### 顶栏两端对齐的是墨迹，不是盒子

内容锁是全站唯一的左右基准：标题、卡片、面板的边缘都压着它。顶栏必须压同一条线，
而**盒子压着线不等于看着齐** —— 描边拿掉之后，两端各自多出一截不可见的空白：

| | 空白从哪来 | 1728px 下实测 |
|---|---|---|
| 左端 | 标记在 32 的 viewBox 里左右各留 4.05（笔画 3.1 + 圆头），19px 下 = 2.4px | 墨迹缩进 2.4px |
| 右端 | 最后那个控件自己的内边距（官网 `.lang` 11px，门户 `.chip` 10px / `.chip.icon` 5px） | 墨迹缩进 6~11px |

两端都用负外边距把那截吐回去，**只挪盒子不挪墨迹**：左端拉 2px 而不是 2.4
（圆头本来就该比直边多探出去一点点才看着齐），右端拉满自己的内边距。
改完实测左 0.4px、右 0~1px，剩下的是字形自带的 side bearing，去不掉也不该去。
**改了 `.mk` 的尺寸要重算左端那个数。**

（悬停时那块浅灰底会探进 `--pad` 的留白里 —— 那正是它该在的地方，
390px 下 `scrollWidth == innerWidth`，没有横向溢出。）

### 首屏只放首屏

`.tile.hero` 有 `min-height:calc(100svh - 48px)`（48px 是导航条）。窗口高一点，
下一屏那块深色就会从底下探进来半截 —— 那半截既读不出内容，又把「一屏一个主体」
直接作废。`svh` 而不是 `dvh`：`dvh` 随移动端工具条伸缩跳数，`svh` 取工具条展开时的
高度，也就是「保证不被切到」的那一档。`min-height` 不是 `height`，窗口矮时内容照样自己撑开。

- 每一屏一个主体，四周大量安静的留白。
- **除了「产品渲染」之外任何地方不许有阴影**——卡片、按钮、文字都不许。
  唯一那道投影 `rgba(0,0,0,.22) 3px 5px 30px` 只给停在平面上的设备。
- **不许用渐变做氛围。**（唯一例外：首屏底纹那团蓝光，甲方 09-05 拍板，限度见 §7.5。）
- 圆角语法只有三档：`8px` 紧凑工具、`18px` 大面、`999px` 只给主 CTA 和 pill。中间档不许有。

## 6. 主体是什么

wanctl 没有硬件，所以主体分两类，**都是真的**：

1. **双屏真实场景**（首屏）：一台笔记本和一部手机，外壳是**真机渲染图**
   （09-05 起：iPhone 17 Pro 宇宙橙 + MacBook Pro 银，`site/assets/iphone.webp` · `macbook.webp`，
   带透明通道，屏幕那块在图里是个透明的洞），
   **屏幕里跑的是活的产品界面**——笔记本里终端真的在敲命令，手机里真的能按那个蓝色按钮。
   所谓产品渲染图，渲染的就是产品自己。
   壳之前是 CSS 画的，换成真机不是换主张：甲方 09-05 拿来了壳的图，而一台真的 iPhone
   比一块画出来的圆角矩形更符合「官网上不出现任何不存在的东西」。活界面垫在壳底下、
   壳压在上面不接事件，所以边框、圆角、灵动岛、刘海全是图，按钮照样能按。
   手机屏里的**状态栏（9:41、信号、Wi-Fi、电量）和 home 条是 iOS 自己的东西**，画在屏那一层里，
   跟灵动岛一起把这块屏坐实成一部正在运行 iOS 的手机；它们对读屏器不存在。
   屏那一层在壳里的位置和圆角是 `tools/frames.py` 按像素量出来的，**别手改，重新量**。
   **屏里的审批页按 iOS 的尺子排**（09-05 下午，甲方：「太小了，按钮比例不对，内容也有问题」）：
   `--pt` 是一个 iOS 点（iPhone 17 Pro 的屏 402pt 宽），字号 17 / 22 / 13pt、按钮 50pt 高的胶囊、
   分组卡 20pt 圆角、上安全区 54pt、下安全区 34pt，全用这一把尺，手机放大缩小比例不变。
   版式是 iOS 的请求页：导航标题（字标 + wanctl）→ 谁在请求（名字、短指纹、「想运行一条命令」）
   → 一张分组卡（设备 / 命令）→ 秒表 → 三颗胶囊按钮压在 home 条的安全区上。
   屏底是分组页那种浅灰（`--canvas-2`），卡片和次级按钮是白的；没有新颜色。
   **手机的宽是舞台的尺子**（`.stage` 的 `--pw`）：视口宽的 17%，封顶 300px，再被折线封顶
   （屏底不过 `100svh`），地板 150；笔记本按等高跟着（宽 = 3.39 × 手机宽），终端字号也按
   笔记本的宽算。1440×900 下手机 242 宽、笔记本 819；2000 宽的屏上 300 / 1017。
   两块屏**高度相等**（笔记本的宽由手机的宽算出来），手机不是笔记本旁边的小挂件：
   它才是要人伸手去点的那一块，屏内字号按它自己的宽度定，不跟着笔记本缩。
   整个舞台要落在折线以上 —— 不只 1440×900：`--pw` 里那条 `(100svh − 400px) / 2.07`
   就是这句话，任何高度的窗口都成立；否则那颗蓝按钮就白做了。
2. **被放大的真实界面**（往下滚的每一屏）：审批卡片、设备列表、身份核对，
   单个拎出来放大到主体尺寸，居中，带那道唯一的投影。
   这类面板默认左对齐（它们是记录）；**只有身份核对那张是居中的**——
   它不是一条记录而是一次比对，两端对称、链路在正中，居中才是它本来的样子。

## 6.5 独立评审（09-04 起）

**实现者不自验这条，在"好不好看"上一样成立。**在此之前，正确性一直是量出来的
（对比度算、溢出量、动效按真实毫秒采样），但视觉判断从头到尾是同一个人做同一个人验，
唯一的独立视角是甲方——那是最该省着花的资源。

做法（源自 Anshu Chimala 在 Lenny's Newsletter 那篇的 Technique 3）：
起一个**只拿到截图**的子 agent，看不到代码、看不到设计理由、看不到之前任何一轮，
让它说出这页在追什么美学、想象顶级工作室会怎么执行、指出差距、打分。
**停止条件不要告诉它**，让打分保持客观。

**评审的结论不是判决。**首轮 5/10 里有 4 条经实测是错的（分段控件内边距并不跳、
接近律并没有反、首屏底部内边距是 88 不是 43、次级链接和主按钮同为 17px），
1 条被夸大（手机圆角差 1px 不是"明显"）。它也不知道哪些是甲方已经拍过板的取舍。
**所以流程是：评审给线索 → 逐条量 → 量得住的才改。**

它最好的一条是纯手艺之外的：审批卡里「一直允许」是一次持久授权，
却做成了三个按钮里最轻的一行蓝字，而后果最轻的「拒绝」是块厚灰板。
**按钮层级要按后果排，不按语气排。**

## 6.2 标识

**标记是一个 `w`，最后一笔越过其余三笔的顶。** 一眼是字母，看清了是「一条路走完，
末尾抬起来」—— 那一下就是勾。产品的核心动作是**你点头**，所以标记画的是那一下。

这条是 2026-09-04 傍晚甲方推翻自己上午的决定改的，两次都有理由，别当成摇摆：

- 上午的结论是**没有图形标记，只有字标**。当时在用的是一把挂锁（安全类产品里最不用
  动脑子的那个选择），试过三个替代并在 16 / 20 / 32 / 72px 上实渲（停在竖线前的一条线、
  两端与断开的中段、终端光标块），三个都是拿一个弱符号换另一个弱符号，
  所以是减掉它而不是替换它。
- 傍晚重开这一题时，四个候选仍然按 16 / 20 / 32 / 72px 实渲了才挑
  （A 平写的 `w` · B 末笔上扬 · C 末端一个实心点 · D 中间断开）。
  **C 在 16px 上糊成一团**——那个点跟笔画粘在一起；**D 的意思只在 72px 上看得见**，
  跟上午被否掉的「两端与断开的中段」是同一种失败。B 是唯一一个既在 16px 上立得住、
  又说了一句只有 wanctl 能说的话的：它不是挂锁，也不是 `>_`。

**一条路径，两种装法。** `site/assets/mark.svg` 与 `internal/portal/web/mark.svg`
是同一个文件（`go:embed` 跨不出包目录，只能各存一份）：方框版给标签页图标，
深色圆角方 + 反白笔画，路径下移 1.3 做几何居中（圆头把墨迹上下撑得不对称）。
页面里内嵌的那份不移也不带方框，`currentColor` 描边跟着字标走 —— 那样它跟字标的
视觉基线才对得上，也不引入第二种墨色。

**字母画成路径而不是 `<text>`**：favicon 的 SVG 由浏览器独立渲染，拿不到页面的
`@font-face`，用 `<text>` 会掉到各平台的系统字体上，同一个标记在三个操作系统上长三个样。

**改了标记要同时改五处** —— 两个 `mark.svg`、`site/index.html`、门户的
`index.html` 与三张认证页、以及 `tools/og.html`，然后重跑 `tools/og.sh`。

## 7. 动效

- 只用 ease-out 族。按压态统一 `transform: scale(0.95)`（apple 的系统级微交互）。
- 不动 layout 属性；每条动画配 `prefers-reduced-motion: reduce` 降级为瞬时。
- 内容可见性不绑在 class 触发的 transition 上：无头渲染下首屏必须完整可见。
- **首屏必须自己动起来。** 2026-09-04 实测：一块完全静止的设备渲染图会被当成图片，
  甲方自己都差点没去点它。所以「产品渲染」里跑的界面必须有**不靠鼠标就在变的东西**。
  秒表是最便宜也最诚实的那一个——它同时是真的，`wanctl exec` 就是阻塞在那儿等人回答。
- **开场动画的终局必须等于 CSS 的默认状态**，中途状态由 JS 临时加类实现（手机的
  `.asleep`、指纹卡的 `.verifying` 都是这个形状）。这样无 JS、无头渲染、
  reduced-motion 三条路看到的都是终局，不会有人看见一块空屏。
- 一个信号在移动端可能落在折线以下。首屏的秒表因此有两份：终端里一份，手机屏上一份
  （`pending 0:12`）——移动端是手机在上、终端在下，落地时只看得见后者。

### 7.5 首屏背景：看不见的密文场（09-05）

甲方 09-05 要的：像 ChatGPT 官网那样，背景是各种字符，鼠标划过、点击有涟漪。
落地成 `site/assets/field.js`，一块垫在首屏底下的 canvas（`.field`，`z-index:-1`，
首屏靠 `isolation:isolate` 自成层叠上下文）。

**静止时一格都不画。** 这是甲方追加的一句（「鼠标没有滚动的时候看不到字符」），也正好
让它绕开 §8 的两条红线（密排噪点场、高密度构图）：没人碰的时候首屏就是原来那块白，
字符那部分零开销 —— 没人碰的时候循环降到 30fps，只画那几圈线和沿圈流动的高光（见下）。

它露出来的是什么：**base64 的字节**。relay 看得见的只有密文（§6、首页第四屏），
所以桌面底下铺着的就是那种东西，跟页面上那两条指纹同一套字母表。

- 鼠标划过：经过的地方解析出一团 —— 边缘是「·」，中心是字，同一格闪着换字，半秒内散掉。
  划得快透镜略大，划过的整段都亮（两帧之间按线段注入，不留缝）。指针停住不动也照散。
- 点一下：一圈蓝色的波从点的地方推出去。蓝在这套系统里是「活的 / 已核对」，
  这一下是「你点了头」；手机屏里按「允许一次」也会推出一圈 —— 那正是那个动作。
- 露出来的形状不是均匀的圆盘：底下有一层慢慢演化的 simplex 噪声在决定哪几格是字、
  哪几格是点、哪几格是空，像手电筒照在一片本来就在那里的东西上。种子固定，截图可比。

纪律：

- 颜色只有 `--ink-3`（它本来就是「仅装饰」那一档，不承载文字）和 `--blue`，
  都从 `:root` 读，不抄一份色值。
- 字从不压在文字底下：h1 / lead / CTA 的盒子外扩 28px（纵向六成）再软化 44px，
  那片里一律不画。切中文之后禁区跟着新标题走（ResizeObserver 盯着首屏和这三个盒子）。
- `prefers-reduced-motion`：不装监听、不建网格。无 JS：白底。
  三条路看到的都是原样 —— §7「终局等于默认状态」在这里的形态是「默认状态就是什么都没有」。
- 画布 `pointer-events:none`，指针事件挂在 section 上；手机屏里那三个按钮、两个 CTA 照常能按。
- 格子 13×21（行高 1.75，跟 `.term` 一样）、字号 12；560 以下 12×20 / 11。
  字形预先画进图集，逐格 `drawImage`，1440×900 满负荷一帧不到 1ms。
- 首屏滚出视口、标签页藏起来：停。

**底纹（同一天的第二轮）。** 甲方看了第一版之后要了两样：标题那一块要干净；整个首屏底下
再叠一层淡淡的 svg，「渐变或者线条勾勒的效果，突出 wanctl 主题」。落地成 `field.js` 建的
一块 `<svg class="backdrop">`，垫在密文场底下，静止时就在：

- **一团光**：蓝色的径向渐变，圆心在首屏正中，峰值透明度 0.06，到 0.55 倍长边处归零。
  这是 §8「不许用渐变做氛围」在全站唯一的例外，甲方 09-05 拍板；限度是**只用 `--blue`、
  只在首屏底纹、峰值不超过 0.07**。别把它当先例往别处铺。
- **几圈线 + 高光弧**（第三到五轮，「线条会渐变 + 流动」，第五轮甲方说明白了：
  「是高光弧形沿着圆圈流动」）：同心圆，圆心也在首屏正中，`--blue` 一像素线、透明度 0.14、
  远处再淡，从半径 120 起每 120 一圈，**静止**。每圈按周长分一到三段高光弧：一条彗尾，
  头 0.5、往后渐隐（conic 渐变沿弧画）、4px 的高斯柔边（同色不偏移的 shadowBlur，
  甲方定稿后又要的「调低透明度、带点模糊」），弧长 340px（小圈封顶为周长六成），沿线以
  90px/s 流，大圈小圈上走得一样快，相邻两圈反向、相位错开。画在密文场那块 canvas 上，
  没人碰的时候 30fps，一帧远不到 1ms；reduced-motion 下画一帧就停。
  走过的弯路，**都别改回去**：第三轮的圈是 `--hairline` 0.55、光只有 0.6 —— 甲方说
  「太亮」「没动」，圈盖过了光；第三轮的圆心追着两块屏之间那个点（relay 站的位置）跑，
  甲方说「不居中」—— 页面居中的标题和 CTA 衬得它偏右，意象让位给版式；
  第四轮把「流动」误会成圈自己往外漫，甲方纠正。
- **字符和圈线都直接从标题底下过。** 曾经给标题、导语、CTA 挖过一块池子（那里不画字、
  遮掉圈线），先是每个盒子各管一片，后来合成一个大池子宽羽化 —— 甲方看了两轮都说
  「标题有一层背景色」：周围有纹理、中间是白，眼睛就把那块白读成一块底色。
  09-05 第三轮删了。**别再挖。** 发丝线和 12px 的淡灰字从 56px 的粗标题底下过，不碍读；
  导语底下只在划过和波经过的那一两秒有字，也不碍。

验收：`node tools/field-shot.mjs --base http://127.0.0.1:8688 --out <目录>` ——
真浏览器、真毫秒、真指针事件（CDP `Input.dispatchMouseEvent`），查静止无字但圈在动
（隔 1.5s 两次读画布必须不同）/ 光居中 / 划过有字 / 移开散尽 / 无横向溢出 / 手机按钮可点 /
reduced 下圈画一帧就停（两次读画布必须相同），
桌面和手机各截静止、悬停、涟漪三档。旋钮全在 `field.js` 顶部的 `P`，
浏览器里 `window.__field.P` 可以现场调。

## 8. 硬禁

- 第二个强调色。任何「点我」信号都是 `--blue`。
- 卡片 / 按钮 / 文字上的阴影。
- 装饰性渐变、密排噪点场。（首屏底下那片密文不在此列：它静止时一格都不画，见 §7.5。）
- 玻璃拟态**作为装饰**。唯一例外：顶部导航条的 `backdrop-filter`，
  它是苹果那套里承担功能的元素（吸顶条压在内容上必须半透），不是装饰。
  `rules.md` 禁的是「默认玻璃拟态」，这一处是有理由的例外，别当 bug 修掉。
- 正文用 500 字重。正文行高低于 1.47。
- 整幅 tile 圆角。
- **顶栏底下的分隔线**（2026-09-04 甲方拍板，官网和门户同时拿掉）。全幅试过、
  收在内容锁以内也试过，两种都不对：那条线在一个只放着字标和两三个次级控件的横条
  底下横过整页，把页面切成两截，而上半截并没有需要被隔开的东西。吸顶时的边界由
  `backdrop-filter` 承担 —— 内容从底下滑过去被抹成一片柔光，那本来就是这层半透的职责；
  页面停在顶部时顶栏就该化进页面里。
- **顶栏里的描边胶囊**。线拿掉之后，一圈描边会成为那条横带里最重的东西，
  而它们只是次级控件。悬停的浅灰底已经说明它们能点。
  （设备标题行里那个齿轮不在此列：那里是内容不是外壳，旁边还站着一个描边的 `select`。）
- 官网出现任何 wanctl 不存在的东西（硬件、未实现的能力、真实部署的机器名与域名）。
- 其余全部遵守 `~/.claude/skills/design-dna/rules.md`。

## 9. 三个表面的差异

同一套 DNA，三种密度：

| | 官网 `site/` | 门户 `internal/portal/` | 文档站 `site/docs/` |
|---|---|---|---|
| 密度 | 极疏。一屏一个主体 | 中。一屏看完六台，但仍不做密排 | 密。三栏，一屏是给人读完一整节的 |
| 语言 | 英文为主，中文可切 | 同左（09-04 拍板改的，含三张认证页） | 同左，**正文也跟着切**：每篇一页两份正文，见 `docs/portal/README.md` |
| 正文 | 17px | 15px | 16px / 行高 1.65 |
| 内容锁 | 1440px | 1100px | 1240px（232 左栏 + 正文 + 196 右栏） |
| 数据 | **全部虚构示例**，见 `site/assets/app.js` 顶部 | 真实 | 真实（域名占位符在构建时换成真实实例） |

文档站没有自己的调色板和自己的顶栏：它先加载官网的 `app.css`，再加载
`site/assets/docs.css`。后者只做两件事 —— 补一个当前项底色 `--blue-wash`
（跟门户同值）、把 `--maxw` 收到 1240 —— 剩下的密度全是排版。
`tools/contrast.py` 因此按「app.css + docs.css 叠出来的 `:root`」验它，
跟浏览器看到的是同一份。

排版参照 api-docs.deepseek.com（`PORTAL-HANDOFF.md` §4 实截）：三栏之间只有发丝线、
不上背景；面包屑最后一节是浅蓝胶囊；行内代码是浅灰圆角块；表格全边框加灰表头。
**代码块不上语法高亮** —— 正文里的命令是要照抄去跑的，多一套颜色只会多一个
跟「蓝色 = 可点」打架的信号。

门户里还有三张**登录之前**的页面（`/auth/login` · `/pending` · `/enroll`），
它们既不是海报也不是工具，是 §5 那张表里的「打断」：一列锁到 25rem、竖向居中、
段落仍旧左对齐。整页只有设备授权页那块要复制的授权码是居中的 —— 它是个物件，不是句子。
它们跟 SPA 共用 `/assets/app.css`（`handleAsset` 故意不鉴权），所以改 token 会同时改到它们。
