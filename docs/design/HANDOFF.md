## 3.5 首屏为什么会被当成图片，怎么修的（09-04）

甲方原话：「一进来这块是静态的我差点以为是图片了……其他用户看到这些肯定也会以为是图片」。

**根因**：`boot()` 走的是 instant 分支，落地时命令已经画完、连光标都不闪 ——
**零运动**。而设备外壳恰恰是「这是营销配图」最强的先验信号，两件事叠在一起就成了图片。

三层修法，全部已上：

1. **手机会亮一下**。开场手机屏是黑的 → 笔记本带光标敲出命令 → 终端开始等待 →
   手机亮起、请求升上来。这就是 `DESIGN.md` 第 1 节那句场景句，之前只写在纸上。
2. **等待是有时长的**：`waiting for the owner…  0:07`，每秒跳一次。会走字的东西不可能
   是照片，而且它是真的（`wanctl exec` 真的阻塞在那儿）。十秒没人动，agent 自己再补一句
   `still waiting — it's your call`，不给页面加新元素。
3. **「该你了」有指向**：主按钮每 3.4 秒轻呼吸两下；手机放大到与笔记本等高
   （184px 宽），屏内字号同比放大；中段补上请求方的短指纹
   （`SHA256:fJoz5aA…DOAEo=`，形状同 `transport.ShortFingerprint`），
   动作区上方加一道分隔线。

后续每一轮请求也会「动一下」（内容升起 + 手机抬一下），
**但命中已签规则直接放行的那一轮不动** —— 动=需要你，不动=不需要你。

期间修掉三个只有真浏览器才会暴露的问题：

- 手机上的秒表 `pend.textContent = …` 把那颗活体指示点一起抹掉了（第一次跳动就没了）。
- 浏览器允许在连字符后折行，`--epochs` 被断成 `--` / `epochs`，读起来像两个参数。
  每个 token 各自 `nowrap`，超过 16 字的长 token（`--query-gpu=memory.used`）才放开内部断行。
- 手机放大后整个舞台掉到折线以下，那颗蓝按钮反而看不见了。首屏上留白收窄
  （`.tile.hero`）+ 舞台上边距收窄，现在 1440×900 下按钮落在 613–649px。

| | GitHub | 中国镜像（官方 relay） |
|---|---|---|
| macOS · Linux | `curl -fsSL https://github.com/Daily-AC/wanctl/releases/latest/download/install.sh \| sh` | `curl -fsSL https://wanctl-relay.z10.dev/install.sh \| sh` |

GitHub。机制在 `internal/relay/dist.go` 的 `installerHandler` + `WANCTL_PUBLIC_ORIGIN`。

页面上用两个分段控件（系统 × 下载源）把四条收成一条：
系统按 UA 猜初值，下载源跟着页面语言（中文默认镜像），**用户手点过就不再替他改主意**。

**副作用要知道**：官网公开推荐这个 URL 之后，陌生人会从甲方的个人生产 relay 拉安装包。
它今天本来就对任何人返回 200，所以安全面没变，变的是流量。

## 3.10 部署（09-04，已上线）

按 `fleet-deploy`：静态文件在 **ls** `/srv/www/wc.z10.dev`，**hk 只做 TLS 终止 + 反代**。
`wc` 是一级子域、`wc.lab` 是二级，两个都命中已有泛域名，**DNS 一条都没加、证书一张都没签**。
两个名字写在同一个 server block 里（照抄邻居 `sifter.z10.dev` 的样板）：
橙云那个分享出去有 CF 边缘缓存，灰云那个给大陆访客绕开 CF 免费版的阿姆斯特丹绕道。

- ls：`/etc/nginx/sites-available/wc`（8443，证书 `/srv/hyakki/certs/`）
- hk：`/etc/nginx/conf.d/30-wc.z10.dev.conf`（`proxy_pass https://49.232.31.177:8443`）
- 发布：**`tools/deploy.sh`**

**发布脚本为什么要改文件而不是直接 rsync**：实测 CF 会用自己的 Browser Cache TTL
（免费版默认 4h）**改写浏览器看到的 `Cache-Control`，源站写 `no-cache` 也拦不住**——
下次改版，回头客最多 4 小时还在跑旧 CSS 配新 HTML。所以脚本在发布副本上给
`app.css` / `app.js` 打内容指纹（`?v=<md5 前 10 位>`），换内容就是换 URL，
nginx 那边这两类因此可以放心 `immutable`。**本地开发不带指纹，不用跑构建。**

两个实测到的坑：

- **macOS 的 `tar` 会带 `._*` 影子文件**（扩展属性），那些会被公开服务出去。
  脚本里 `COPYFILE_DISABLE=1` + `--no-xattrs` + 落地后再 `find -name '._*' -delete`。
- **`chown -R www-data` 之后 ubuntu 就读不了那个目录了**，核验（`find | wc -l`、`du`）
  必须排在 chown 之前，否则整条命令在最后一步 permission denied。

实测缓存分布：字体 `cf-cache-status: HIT`（immutable 一年，116K 全走 CF 边缘不碰 hk），
og.png / mark.svg HIT，指纹后的 css/js immutable，HTML `no-cache` + `DYNAMIC`
（CF 免费版本来就不缓存 HTML，15K 而已）。橙云首字节 ~1.6s、灰云 ~0.69s，
和 `fleet-deploy` 里记的阿姆斯特丹绕道口径一致。

**09-04 夜补：目录重定向会泄漏源站端口。** `wc.z10.dev/docs`（不带斜杠）曾被 301 到 `wc.z10.dev:8443/docs/`：
hk 反代到 ls 的 8443，nginx 给目录补斜杠时把自己监听的端口写进了 Location。修法是在 ls 的
`/etc/nginx/sites-available/wc` 加 `absolute_redirect off;`（备份在同目录 `.bak-20260904`），已重载并实测三条 URL 都 301 到干净路径。
以后加任何有子目录的静态站都要带这一行。

## 3.11 中文排版 + 手机版式（09-04 晚，issue #17，分支 `site-mobile-cjk`）

甲方在手机上报了两件事：中文一切过去**每台设备上都难看**；手机版「适配了，但看着别扭」。

**中文**：字号阶和负字距整套是给 Schibsted Grotesk 的拉丁调的，原样套到汉字上三处不对
（负字距把笔画挤在一起、1.47 行高太紧、woff2 是拉丁子集所以一句里汉字掉到系统字体
而字母数字还在 Schibsted）。修法整块锁在 `:lang(zh)` 里，`lang` 属性本来就由 `applyLang`
翻，**JS 一行没动**：换成系统 CJK 无衬线连同它自己的拉丁（macOS 的 `-apple-system`
就是 SF Pro + PingFang 这对）、字距一律 0（字标和 `.door .addr` 两处例外，都是纯拉丁）、
正文行高 1.6 标题 1.2。**标题字重维持 600**，56px 的 PingFang Semibold 实渲过，不显重。

**中文标题的断行是这一轮唯一没有纯 CSS 解的**。浏览器可以在任意两个汉字之间断开，
`text-wrap` 三种模式实测全都断词（balance 断「什|么」、pretty 断「不|会」、
默认留孤字「跑。」），`word-break:auto-phrase` 在 zh-CN 上是**空操作**（断点一个没动，
Chrome 那套分词换行目前只对日文生效，别再试）。解法是把分句包成 `display:inline-block`
的 `.cl` 盒子——盒子是原子的，断点只能落在分句之间，分句自己装不下时照样内部换行。
只包实测断得难看的两条（`#decide`、`#relay`）。

顺带一条反直觉的：**`text-wrap:balance` 在中文里宽窄两头结论相反**。宽屏它好
（首屏 lead 断在句号上）；390 下它为了拉齐把行做到 13~14 字，而那一栏放得下 19 字，
左对齐的段落右边就恒定空一条白。所以只有**左对齐**的 lead 在 ≤760 翻成 `pretty`，
居中的海报 lead 三处不动。

**手机版式**四条，全部是减法，不是加手机专用版式：

## 3.12 系统性扫一遍，而不是一个一个找（09-05，分支 `site-sweep`）

甲方原话：「不要让我发现一个改一个，这效率太低了」。所以先有量具，再有修法：

顶栏与语言开关是否够得着、每一屏的高度对视口、13px 以下的文字、40×40 以下的
按压面（**用 elementFromPoint 往外探**，不看盒子 —— 透明的 `::after` 也算数）、
表格对着那个该滚它的盒子、吸顶条压住的内容、文档站两根侧栏滚过之后还在不在、
控制台和网络。它自己起 headless Chrome 走 CDP（不用 `--window-size`，那个会被
钳到 500px；也不用共享的 Playwright MCP，一轮要导航三百多次）。

**一个真踩到的坑：`--remote-debugging-port` 不许猜。** 猜的端口被另一个 agent 的
headless Chrome 占着时，我们的 spawn 绑不上，`/json` 却照样有响应 —— 于是整轮
320 个数据点量的是**别人的门户页面**，全程零报错。现在传 `--remote-debugging-port=0`，
端口从自己 profile 里的 `DevToolsActivePort` 读回来。

扫出来 6 条 broken/wrong + 3 条判为不修，全部记在 PR 里。修完之后 320 个点：
零横向溢出、零控制台/网络噪声、零被裁的顶栏控件、语言开关处处够得着。
**1440 英文对 `origin/main` 逐像素相同**（官网 0/5,477,760；文档站四页各 0），
量法是脚本执行关掉之后整页截图对比，另外再比一次开着脚本的全元素盒子。
两条因此被压回窄屏断点：表格的遮罩、表格里行内代码的 13px 地板 —— 缺陷是在
手机上量到的，没有理由动那一档冻着的桌面。字标也因此不跟着链接撑到 48px：
它的行盒高度是分数，撑满之后标记居中差半个像素，1440 上实测 78 个像素不一致。

**这一轮学到的两条**：

- **「一行装完」那道遮罩以前挂在 ≤560，是猜的。** 实测 768 下英文那条 GitHub
  命令 762px 装进 624px，还有 138px 在框外而遮罩早已下线。改成 app.js 按
  `scrollWidth > clientWidth` 挂 `.cmdline.more`，量的是溢出本身，1440 自动没有。
- **两个断点讲同一件事就得是同一个数。** 舞台在 ≤760 竖排，笔记本却在 ≤560 才
  退场，于是 561~760 这一档首屏 1055~1062px 高、笔记本被折线切一半 ——
  §3.11 在 ≤560 修掉的正是这个。两条现在都在 760。
