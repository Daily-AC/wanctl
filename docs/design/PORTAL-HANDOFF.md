**它跟 `DESIGN.md` 不打架，是同一族**：白底、近黑正文、单一蓝（链接与当前项）、

## 6. 施工中自己拍的板（甲方未逐条过目，要改说一声）

- **设备页也有一个齿轮。** 被砍掉的「模式」tab 里其实还装着 LAN 直连、飞书审批、
  webhook 三个**每设备的设置**，它们不属于「待审批 / 信任 / 活动」任何一个。
  让齿轮在哪一层就是哪一层的设置，比硬塞第四个 tab 诚实。
- **设置和设备设置是页面，不是覆盖层。** 覆盖层会把顶栏连同「我现在是哪个命名空间、
  指纹是多少」一起盖掉 —— 一个安全工具不该这样。
- **设备卡砍掉了指纹。** 判据就是这一轮的消融判据：拿掉它，谁损失了可以据以行动的东西？
  没有 —— 没人在清单页上读一串截断到 30 字的哈希。指纹留在设备详情页，那儿是全长、可核对的。
- **加了一个语义红 `--red #d70015`**（白底 5.38、灰底 4.94，`tools/contrast.py` 已验）。
  它**不是第二个强调色**：只陈述 denied / 投递失败 / 危险命令首词，从不承担「点我」。
  在线 / 离线故意不引入绿，用实心点 vs 空心圈。
- **内容锁 1100px**，不是官网的 1440。官网是海报要用掉整幅宽度；门户是工具，
  摊到 1440 会把设备卡稀释成一条，眼睛横扫的距离也过长。
- **绝对时间统一成 `2026-08-26 16:14`**。`toLocaleString()` 按地区给出
  `8/26/2026, 4:14:35 PM`：秒是噪声，日月顺序还随地区变，而这些数字常要跟日志对齐。
- **顺手关掉了 issue #10**（非管理员能通过 hash 打开管理员视图）。修法是路由前先等
  `/api/me` 到手、再按角色拦，不是靠导航项的 `hidden`。

以下是做手机布局那一轮拍的（issue #24）：

- **「侧栏 + 内容」在窄屏上拆成两级，不是把侧栏摞到内容上面。** 摞起来的代价是
  要滚过整张菜单才够得着你点的那一节，而菜单读起来还像是页面的一部分（甲方
  在 412px 的手机上一眼就看出来了）。改成 iOS 设置那套：清单是一屏，点进去
  那一节是另一屏，顶上一枚人字形回清单。**两级都写进地址**（`#settings` 是清单、
  `#settings/tokens` 是其中一节），所以系统返回键是对的，链接发给自己也回到同一处。
  实现全在 `app.css` 的 760 断点里，宽屏 1200 实测零像素差异 —— 宽屏两级永远同时在，
  那两个地址在那里渲染出来就是同一张页面。齿轮因此改成落在 `#settings`（清单）。
  **门户里只有设置一处是这个形状**：设备设置页是一列卡片，没有侧栏，不必改。
- **清单那一屏上不留「当前项」高亮。** 高亮的是你上次去过的地方，不是你此刻在的地方 ——
  窄屏上你此刻不在任何一节里。宽屏照旧。
- **清单每行右端加了一枚人字形**（`.back` 那条路径的镜像，`--ink-3` 描边，CSS 背景图）。
  它说「点这里会推开一屏」。不是新图标，是同一枚；也只在 760 以下出现。
  外链那一条（文档）不给，它的 ↗ 已经在标签里。
- **浮层的高度改用 `svh`。** 手机浏览器的 `vh` 是地址栏收起之后的那个大视口，
  按它算出来的浮层比眼前看得见的那块高，底下那排按钮正好落在屏幕外面 ——
  甲方那张「完成被切掉半截」的截图就是这么来的。两条声明都留着，不认 `svh` 的读第一条。
- **更新日志那张浮层分三段**：标题与「完成」钉住，中间那层自己滚。整块一起滚的话，
  手机上想关掉它得先把十几张版本卡整个读完一遍。`.modal.wide` 顺势改名 `.modal.sheet`
  —— 全站只有它一处在用，而它要的不是「宽」，是「一张有固定高度的纸」。
- **`md()` 的围栏不再认列首那一条。** 发布说明里的代码块几乎都缩在某个列表项底下，
  而缩进过的围栏以前会掉进段落分支，被行内代码那条正则啃成「两个字面反引号 +
  一段行内 code」。改成 `/^[ \t]*```/`，并按开栏的缩进量去掉每行同样多的前导空格；
  段落续行的守卫也一起放宽，否则围栏会被前一段吸进去。输出改 `<pre><code>`。
  **`tools/portalpreview/fixtures.js` 里那条 v0.3.4 的正文换成了带缩进围栏的真实形状** ——
  以前那条是三行平铺的列表，工装因此永远复现不出线上这个 bug。

以下是做认证页那一轮拍的：

- **三张页面从 Go 常量搬成 `web/*.html` + `html/template`。** 两个理由：预览工装
  现在发的就是服务端发的那批字节（以前要靠一个临时脚本把 `%[1]s` 那套格式动词
  重新实现一遍，而一个会「重新推导」被观察对象的预览是会跟它不一致的）；
  以及 `html/template` 按上下文转义，唯一来自外部的值（GitHub 登录名）没法变成标记
  ——旧的 `pendingPage` 是 `fmt.Fprintf` 加一个手写转义器。
- **`/assets/` 不再发任何 `.html`。** 页面模板跟样式表住在同一个目录里，
  而 `/assets/index.html` 以前真的会把带着 `__V__` 占位符的原始页面发出去。
- **等待邀请页加了「退出登录」。** 它以前是个死胡同：用错账号登进来的人没有任何出口，
  只能自己去清 cookie。`/auth/logout` 端点一直在，只是没有任何界面调用它。
- **CSP 去掉了 `fonts.googleapis.com` / `fonts.gstatic.com` 两条放行。**
  字体早就自托管了，全仓库没有一处引用它们。
- **头像整块删掉了。** `/api/me` 以前拿账号 id 拼一个 `avatars.githubusercontent.com`
  的 URL 给 SPA，而门户自己的 CSP 是 `img-src 'self' data:` —— 浏览器每次都拒绝，
  每次打开还留一条违规。09-04 用真 Chrome 对着真服务端测过（见第 10 节）。
  反过来放宽 CSP 不划算：那等于让一个安全控制台每次加载都向 GitHub 发一次跨域请求，
  换一个装饰。**字母章留着**（那本来就是所有人一直看到的东西）。
- **顶栏的分隔线拿掉了，官网同步**（甲方拍板：「这个横线简直是祸害精」）。
  连带把顶栏里三个描边胶囊的边框也去了 —— 线没了之后它们成了那条横带里最重的东西。
  官网首屏另加 `min-height:calc(100svh - 48px)`，不让下一屏那块深色探进来半截。
  理由全部落进 `DESIGN.md` §5「首屏只放首屏」和 §8 硬禁。
- **加了图形标记**（甲方推翻自己上午「只留字标」的决定）。四个候选按
  16/20/32/72px 实渲后选了「末笔上扬的 `w`」。选型过程和另外三个为什么被否，
  见 `DESIGN.md` §6.2 —— **那一节现在也列了改标记要同时改的五处**。
- **登录页第二轮减法。** 第一版有三段正文，甲方看了说「不够极简，参考一下 linuxdo 的」。
  linux.do 的登录页是标题加一排按钮、一个字的说明都没有。照那个尺子量，
  「wanctl 是什么」那段是官网的活，砍掉；另两段各压成一行。三张页面同时改成竖向居中
  ——它们各自只有一件事，顶对齐会把那件事挂在上三分之一、下面空掉半屏。

## 8. 三张认证页（已做完）

**登录（新建）· 等待邀请（`/pending`）· 设备授权（`/enroll`）**，都在 `internal/portal/web/`：
`login.html` / `pending.html` / `enroll.html` + 共用的 `auth.js`，共用 `/assets/app.css`
（`handleAsset` 故意不鉴权就是为了这个）。真实服务端 + 真浏览器验过：双语切换、
邀请码兑换（打到 `/auth/redeem`，CSRF 双提交通过）、退出登录、授权码复制。

**为什么加登录页**（甲方认可的三条理由，别再重议）

1. `wanctl.z10.dev` 已经公开印在官网「两扇门」那一屏上。从 wc.z10.dev 点过来的人
   落地就是一个瞬间跳去 GitHub 的白屏，不知道自己被送去授权给谁。
2. 「这是邀请制」以前要等你**已经授权完 GitHub 应用之后**，才在等待邀请页上第一次说。
   顺序反了。
3. 授权一个 OAuth 应用是一次真实的权限授予；零上下文把人弹过去，形状上跟钓鱼一样。

登录页最后只剩五样东西：`Sign in` / 实例域名 / 一句「邀请制」 / 一个按钮 /
一句「不向 GitHub 申请任何权限」。三条理由各占一样，多一个字都没有。
**产品是什么这里一个字都不说** —— 来的人要么从官网点过来、要么是被人邀请来的。

**认证流程的事实**（已核）

- `handleIndex` → `pageAuth`：无 principal 且开了 OAuth → `303 /auth/login?next=…`
- **`/auth/login` 现在渲染页面，`/auth/github` 才种 state cookie 并 302 去 GitHub。**
  拆成两条路径是因为 state 只活 10 分钟：要是渲染页面时就把 state 种下去，
  一张开了十分钟以上的登录页，点下去会变成 400 —— 一个看起来完全正常的点击
- 已登录的人打开 `/auth/login` 直接 303 去 `next`，不给他一张「登录」页
- 回调后 `resolveNamespace`：`resolveOK` → SPA；`resolvePending` → `303 /pending`
- header(SSO) 模式没有 OAuth，三张里的两张（登录 / 等待邀请）在那个模式下 404

## 9. 预览工装怎么用

```sh
tools/portalpreview/serve.sh          # 默认 8724，绑全网卡（手机可开）
```

数据全虚构，写操作一律假装成功。直达状态：`?lang=zh`、`?view=device/bench-02`、
`?view=device/bench-02/settings`、`#settings/downloads`。
三张认证页在 `/login.html` · `/pending.html` · `/enroll.html`（静态渲染，
兑换和退出登录点了没反应 —— 要试那两个得起真服务端，见第 10 节）。
`assets/` 是软链，改 CSS/JS 刷新即可；**改了 `index.html` 或三张认证页要重启服务**。

```sh
node tools/portalpreview/sweep.mjs --out /tmp/sweep     # 全状态 × 7 视口 × 双语的响应式普查
```

**响应式普查 `sweep.mjs`**（09-05 加）。44 个状态 × 7 个视口 × 两种语言，在真 Chrome 里量
横向溢出、浮层出界、文本截断、可横滚的代码块、手机上小于 40×40 的手指靶子、控制台错误，
写出 `sweep.json` + 一行汇总，并在指定宽度截图。`?scene=empty|noask|down` 三个开关造出
空态、无人等待、中继不可达；`--now` 把工装的「现在」钉住，两次普查的截图才逐像素可比。

**它量的是请求的视口宽度，不是 `innerWidth`。** 手机 Chrome 在内容横向溢出时会把**布局视口**
撑宽到内容宽度（实测请求 412 → `innerWidth` 487），屏幕上看得见的仍然是 412 —— 于是
`position:fixed` 的浮层按 487 居中、按 412 显示，看起来就是被推到右边、右缘切掉。
用 `innerWidth` 当基准的量具会说「`scrollWidth === innerWidth`，一切正常」：它量的是
已经被撑坏的那个视口。甲方 09-05 那张手机截图就是这个形状。

**纪律**：`fixtures.js` 的形状必须跟真实端点一致。本轮它撒过一次谎——把 `/api/me`
的 `identity` 填成 SHA256 指纹，而真实端点返回的是登录名，于是 UI 照着假数据把
门户自己的指纹当成「你的编号」显示在人名旁边，甲方一眼看出不对。别再让工装替真代码说话。
**09-05 又抓到第二次**：设备和已信任控制端的指纹在工装里是预先截短再补一个省略号的
（`SHA256:Pn7VqL2mXb4TcZw9…`，22 字），而真实端点给的是恒定 51 字的整串。于是
`renderTrusted` 里那句 `.slice(0, 30)`——它把指纹切成 30 字且**不加任何记号**——
在工装里永远碰不到边界，四个月没人看见。把工装换成真实长度之后，它第一屏就露出来了。

## 10. 不接中继，起一个真的门户

预览工装发的是静态文件：没有 CSP 响应头、没有 Go 模板、没有 CSRF cookie，
所以它验不了认证页真正在做的事。真服务端不需要中继也能起来 —— 只要给 OAuth 三件套
（client id / secret 随便填），`/auth/login` 就会被真的模板渲染出来：

```sh
export WANCTL_CONFIG_DIR=/tmp/portalcfg          # 别动你自己的身份文件
export WANCTL_GITHUB_CLIENT_ID=Iv1_localtest
export WANCTL_GITHUB_CLIENT_SECRET=localtestsecret
export WANCTL_SESSION_SECRET=0123456789abcdef0123456789abcdef
go run . portal -addr 127.0.0.1:8725
```

`/` 会 503（`pageAuth` 先查中继），但 `/auth/login`、`/auth/github`、`/assets/*` 全是真的。
要看 `/pending`：session cookie 就是 `v1.<base64url(json)>.<base64url(hmac-sha256)>`，
用上面那个 secret 自己签一个 `{"provider":"github","sub":"…","login":"…","exp":…}` 塞进去即可
（`handlePending` 解析不出命名空间时会照常渲染页面）。**09-04 就是这么验的**：
双语切换、空码校验、兑换真打到 `/auth/redeem` 并通过 CSRF 双提交、退出登录清掉 cookie、
以及那条头像的 CSP 违规。

**门户**：**没有发新 release、没有换 dist**，所以只重建门户容器。

旧镜像已打 tag `wanctl:rollback-20260904`。

**ls 仍然连不上 GitHub 的 git 端点**（实测 `git-upload-pack` 25 秒零字节，
而同一台机器拉 GitHub 的 HTML 页面是 200 —— 别被那个 200 骗了）。
代码仍走 `git bundle` + scp。**hk 拉 GitHub 是通的（0.39s / 200），
而 hk 与 ls 同在一个 Tailscale 网里**（hk `100.69.190.32` / ls `100.65.98.121`，
ICMP 通、平均 545ms 且抖动大，说明走的是 DERP 中继不是直连）——
所以「在 hk 上开一个只绑 tailnet 地址的轻量 HTTP 代理给 ls 用」是可行的，
公网面不用动，Tailscale 本身就做了两端认证。**尚未实施。**

**甲方给了这条代理一个硬约束：按需用，不做全局代理。** 也就是 ls 上不设
`HTTPS_PROXY` 环境变量、不写 `git config --global http.proxy`，只在真的要拉
GitHub 的那一条命令上临时带（`git -c http.proxy=… fetch`）。

为了一年几次的 `git fetch` 去改一台生产机所有出站流量的路径，代价和收益不成比例。
