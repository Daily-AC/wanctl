# Mission: 理解并参与 wanctl 远程工作区的架构设计

## Why
让维护 wanctl 或为它接入 AI 宿主的开发者，能够解释远程任务为何连续、状态由谁保存、失败后该如何恢复，并据此评审实现与扩展需求。

## Success looks like
- 能画出宿主、控制端、Relay、设备和工作区的职责分工。
- 能区分身份授权、工作区引用、协议连接和执行任务的生命周期。
- 能根据宿主条件选择 CLI、专属 stdio 或共享 HTTP 的绑定方式。
- 能为状态保留、去重、权限与退出写出可核验的验收条件。

## Constraints
- 按广度优先顺序解释系统宏观架构，不预设读者懂进程与 MCP。
- 每篇聚焦一个判断；图、案例和自检服务于该判断。
- 自检可跳过；不以完成阅读代替已经掌握。
- 当前实现以 v0.12.1 为代码基线；未来能力与已验证能力分开描述。

## Out of scope
- 逐行讲解 Go、密码学算法、进程组和底层网络报文。
- 未实现的 PTY、端口转发、持久 Python 内核与宿主原生工具接管。
- 在公开 Docs 保存个人学习进度、聊天记录或设备凭据。
