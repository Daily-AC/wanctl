# wanctl v0.1.7

Android phones and tablets can be wanctl devices. This is the first release to
ship an `android/arm64` artifact, so it is also the first one a phone can
install or update itself from.

Verified end to end against the production relay on a vivo PA2353 (Android 13)
and an Android 16 emulator, in both of the environments an Android device is
driven from — an `adb` shell and a Termux session. They fail differently and
neither substitutes for the other.

## Android support

Six assumptions that hold on every other Unix do not hold here, and each one
breaks at a different layer, so they surface one at a time:

- **No `/etc/resolv.conf`.** Android resolves through `netd`, reachable only via
  bionic's libc, and wanctl ships CGO-free binaries — so the Go resolver fell
  back to `127.0.0.1:53` and *nothing resolved at all*, including the relay the
  agent was just told to use. `internal/androiddns` points the resolver at
  explicit nameservers (`WANCTL_DNS`, then Termux's own `resolv.conf`, then
  public resolvers rotated so a retry reaches a different operator). The
  alternative — an NDK/cgo toolchain for one platform out of six — is rejected
  in `docs/adr/0002-android-resolver.md`, along with what this costs: on
  Android, wanctl does not follow the device's own DNS, and a private zone needs
  `WANCTL_DNS`.
- **`HOME=/` under an `adb` shell**, so the config directory could not be
  created (`mkdir /.config: read-only file system`). The agent now falls back to
  the first writable candidate, Android only.
- **`/bin/sh` exists only from Android 11**; sessions run in `/system/bin/sh`,
  which every build has.
- **`/data` is traverse-only for the shell user** and `os.Root` opens each path
  component, so transfers failed with `openat data/local/tmp: permission denied`
  against a destination that was perfectly writable. An otherwise-unconstrained
  transfer now binds to the target's own directory — narrower than the volume
  root, not wider.
- **Every Android device reports its hostname as `localhost`**, which is both
  meaningless as a device name and a collision between any two phones in a
  namespace. The default now comes from the property service
  (`ro.product.marketname`, then `ro.product.model`), so a device registers as
  e.g. `pa2353`. Two of the same model still collide; pass `--name`.
- **Termux duplicates `argv[0]`.** Go's Android target is always dynamic PIE, so
  the binary requests `/system/bin/linker64` as its interpreter, and Termux's
  exec interceptor re-runs such programs through the linker explicitly — which
  prepends the program path to the argument vector. Every argument shifted one
  slot, making the binary inert in the one environment Android users actually
  type commands in. The duplicate is now detected and dropped.

`wanctl service install` refuses on Android rather than reporting success it did
not achieve: the platform has no service manager an unprivileged process can
install into. `wanctl start` detaches and survives a locked screen — verified
for 25 minutes — but not a reboot.

Details, including what is still unverified, are in `docs/android.md`.

## Fixes

- Stop overriding a device's persisted policy mode. `policy.Open` documents an
  empty mode as "use the persisted one", and both the `--mode` flag help and
  `service install` depend on it — the flag is omitted precisely so a
  portal-side switch survives a restart. `agent.New` filled in `normal` before
  calling it, making that branch unreachable, so a device switched to bypass
  reverted on its next restart while the CLI help promised otherwise. Found on
  Android: the device's `mode` file read `bypass` and the agent still denied
  every command.

## Upgrading

Nothing to do. The Android work is inert on other platforms, and the mode fix
only changes what a flag-less start reads — a device that has never had a mode
persisted still starts in `normal`.

A device that *was* switched to bypass at some point will now stay in bypass
across restarts, which is what the documentation always claimed. If that is not
what you want for a given device, set it explicitly: `wanctl agent --mode
normal` once, or from the portal.

## Also

`scripts/publish-release.sh` gained `wanctl-android-arm64` in its expected
artifact list. That list is a whitelist: a new build target that is not added to
it fails the publish rather than shipping silently — which is the check working,
and the reason v0.1.3's installers once 404'd.
