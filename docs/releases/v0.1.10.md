# wanctl v0.1.10 — withdrawn, never published

The `v0.1.10` tag exists and its pipeline ran, but **no GitLab Release was
published from it and it was never deployed**. Nothing served it. It cannot be
built from either: `scripts/build-apk.sh` fails on that tree with
`find: android/java: No such file or directory`.

That is why it was withdrawn. `.gitignore` opened with a bare `wanctl`, meant
for the built binary at the repository root; a pattern without a leading slash
matches at every depth, so it also matched `android/java/com/***REMOVED***/wanctl/` and
all nine Java files of the Android app were never committed. Local builds worked
because the files were on disk — the APK that passed on-device acceptance was
built from a working tree, not from a clone. `package:apk` is the only job that
compiles Java and it runs on tags only, so the tag itself was the first checkout
that could notice.

The tag could not be deleted (protected tags refuse it), so it is recorded here
rather than quietly disappearing — the same handling `v0.1.8` got, and for the
same reason.

Everything intended for v0.1.10 ships in **v0.1.11**, on top of the `.gitignore`
fix and two tests that fail if the app's sources go missing again.
