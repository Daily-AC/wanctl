# v0.9.1

Makes the WebFetch contract self-describing and isolates request creation from
cached public discovery pages. Clients use `/webfetch/v1`, generate a fresh
nonce and fill `start_url_template`; public discovery no longer contains a ticket.
Existing session URLs keep their original expiry and revocation behavior.
The authenticated portal adds a Connect web AI page that copies a fresh,
cryptographically generated bootstrap URL without creating or approving a grant.

Manifests expose exact device targets, tool schemas, GET templates and complete
continuation prompts. HTML GET errors carry a readable logical `http_status`;
JSON clients retain HTTP error codes. Owner portal denials explain recovery
without disclosing another owner's grant. Diagnostics exclude credentials and
operation contents.

Also includes the merged self-hosted HTTP-MCP wiring and transport guide: Compose
forwards the MCP seed and portal/relay origins, and MCP login copy refers to the
configured portal rather than a specific identity provider. Existing operator
trust settings remain unchanged.

Upgrade relay and portal. No migration or device upgrade beyond v0.9.0 is required.
See [the protocol and owner workflow](../webfetch.md) for the bootstrap change.
