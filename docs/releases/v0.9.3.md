# v0.9.3

Adds OAuth 2.1 to the hosted MCP endpoint, so a web AI that opens a new MCP
session for every tool call can stay signed in. ChatGPT's connector does
exactly that, and under the session-keyed login a successful `wanctl_login` was
followed by `LOGIN REQUIRED` on the very next call.

The endpoint now implements the MCP authorization spec: protected-resource and
authorization-server metadata, dynamic client registration, PKCE, the
authorization-code grant and rotating refresh tokens. The machine endpoints are
served by the relay, which has the seed, the database and the public origin;
the consent page is served by the portal at `/oauth/authorize`, which is the
service that knows how to turn a GitHub login into a namespace. Access tokens
reuse the sealed-envelope format the rebind credential already uses, so a
bearer needs no lookup to authenticate and `WANCTL_MCP_SEED` remains the one
thing whose rotation signs everyone out. See
`docs/adr/0008-mcp-oauth-split-portal-relay.md`.

Each authorization mints one namespace token labelled `oauth:<client name>`,
listed and revocable on the portal's access-token page; `wanctl_logout` revokes
the same token. Registration on its own grants nothing — access starts when a
signed-in person approves the request.

Clients that send no `Authorization` header are unaffected and keep the
per-session `wanctl_login` flow.

Upgrade relay and portal. **Migration 010** adds two tables, so back up the
database first. OAuth turns itself on only when the relay has a database,
`WANCTL_PUBLIC_ORIGIN` and `WANCTL_PORTAL`; there are no new environment
variables. Devices need no upgrade.
